## 一、项目愿景与创新点

玩家被困在一座失控的时间实验室中。实验室会按照固定周期重置，每次重置后，上一轮玩家的行动都会形成一个“时间残影”。残影沿原路线移动并重复当时的操作，玩家要把“过去的自己”变成可靠队友，共同触发机关、穿越时滞射线、打开通道，最终修复时间核心。

### 核心创新

1. **由玩家亲手编排的伙伴**：残影不是预设 NPC，也不是复制当前动作，而是上一轮真实行为的可重复记录。玩家同时扮演行动者与下一轮的关卡设计者。
2. **把失败转化为计划资源**：一次循环没有直接通关也不等于失败，只要留下了有价值的路线、站位或交互时机，就会成为下一轮解法的一部分。
3. **恒速巡行的时间编舞**：玩家只决定在路口向哪里走，不能自由改变基础速度或原地等待；路线长度、驻留板和时滞射线共同决定未来残影的到达节奏。
4. **共享时钟下的代际协作**：每一轮和所有残影使用同一个固定时长、同一个逻辑刻和同一个读秒。旧残影按完整轮次衰减，新旧代际同时行动，玩家需要规划“哪一轮留下什么”。
5. **可观察的因果链**：残影轨迹、代际编号、透明度、关键交互标记和机关连线反馈帮助玩家理解“哪一轮的谁在何时触发了什么”，降低时间解谜常见的试错挫败感。
6. **临时状态与永久状态的对比**：普通物体随循环重置，时间锚点可让特定状态跨循环保留，使后期关卡从“同步协作”升级为“规划哪些改变值得保留”。
7. **确定性回放也是技术特色**：固定时间步长与“位置快照 + 交互事件”混合记录，让残影在不同渲染帧率下仍能稳定复现，创新点既能玩到，也能在答辩中解释和验证。

### 最小创新证明

即使所有扩展功能被砍掉，最终演示也必须清楚呈现以下闭环：

1. 玩家发现单人无法同时激活的两个驻留压力板；
2. 第一轮以恒定基础速度规划路线，被一侧驻留板捕获并等待统一读秒归零；
3. 下一轮开始时残影稳定复现第一轮的完整固定时长，且轨迹/交互有清晰视觉反馈；
4. 当前玩家与过去的自己协作开门并通关。

## 二、核心玩法循环

1. 在轮前准备阶段观察廊道、路口、机关、时滞区域、旧轨迹与出口条件，并预选初始方向。
2. 每轮具有固定时长，玩家不能主动提前截止；当前玩家和全部残影共用 HUD 上唯一的本轮读秒。
3. 轮次开始后角色以固定基础速度持续巡行，玩家只选择方向和交互时机；路线、时滞和驻留位置会完整记录到读秒归零。
4. 读秒归零时，系统在统一轮次边界封装本轮时间线并生成一个新残影。
5. 玩家、普通机关和临时物品恢复到本轮初始状态，轮次计数加一。
6. 所有仍在存活轮数内的残影从逻辑刻 0 开始，按照各自原时间线同步移动与交互。
7. 当前玩家利用一个或多个不同代际的残影完成同步或顺序机关。
8. 满足目标并到达出口时立即完成关卡并记录成绩，无需等待本轮结束。

### 示例：双驻留板门

1. 第一轮，玩家通过路口转向进入左侧驻留板，被机关捕获至本轮结束。
2. 统一读秒归零后，第一轮完整行为变成残影。
3. 第二轮，残影从相同起点、相同逻辑刻自动巡行到左侧驻留板并再次被捕获。
4. 当前玩家选择另一条路线进入右侧驻留板，两块驻留板同时激活。
5. 门打开，当前玩家进入出口。

## 三、游戏规则

### 恒速巡行

- 每轮开始前进入短暂 `READY` 阶段：共享读秒和残影保持冻结，玩家可查看轨迹并预选初始方向；进入 `PLAYING` 后才从 `roundTick = 0` 同时启动。
- 玩家具有固定 `baseSpeed`，不能通过松开按键停下，也没有主动加速/冲刺。`W/A/S/D` 或方向键只负责选择或提前排队下一个方向。
- 地图使用正交网格廊道。到达路口中心时，控制器依次选择“有效的排队方向—保持直行—唯一合法转向—原路返回”，保证角色不会靠顶墙停留来等待时间。
- 只有关卡明确提供的机关可以改变巡行：时滞射线临时降低速度，驻留压力板捕获角色至本轮结束，出口终端完成关卡。
- 需要按 `E` 的交互使用宽容半径和 6–10 tick 输入缓冲，避免恒速经过终端时要求单帧按键。
- 残影回放记录后的位置结果，不重新运行转向、碰撞、驻留或减速逻辑。

#### 恒速巡行原型门禁

这是核心玩法变更，必须在批量制作关卡前先用灰盒验证。原型只需要一个起点、三个路口、一段时滞射线、一个驻留板和一个出口：

1. 松开方向键后角色持续巡行，连续通过 10 次路口不会因浮点误差错过转向；
2. 正面遇到不可通行方向时会按规则继续、转向或返回，不能靠顶墙停留；
3. 五名成员都能在 3 分钟内理解“提前排队方向”，至少四人认为操作可预测；
4. `E` 输入缓冲允许正常经过终端时稳定交互，不需要连续敲击；
5. 同一路线录制并回放后，驻留时刻和时滞后的到达时刻保持一致。

门禁未通过时只调整路口吸附、方向优先级、输入缓冲和速度，不继续制作正式关卡或多残影系统。

### 固定时间循环

- 默认每轮 20 秒，建议关卡配置范围为 12–25 秒；教学关和演示关可以更短，复杂关卡可以更长。
- 同一关卡会话中的每一轮时长保持不变。难度或时长只能在进入/重新开始关卡前确定，不能在中途改变。
- 玩家不能主动提前结束本轮；正常游戏中只在统一读秒归零时切换轮次。
- 当前玩家与所有残影共享 `roundTick` 和 HUD 上唯一的本轮读秒，残影不显示独立秒级倒计时。
- 每条时间线都恰好覆盖本关规定的全部逻辑刻。角色会持续巡行，或被驻留板捕获后记录静止帧，因此残影不会提前消失。
- 读秒归零时，玩家、残影、机关和记录系统先停止在同一逻辑刻，再原子化完成“封装记录—更新残影队列—恢复临时状态—开始下一轮”。
- 满足出口条件会立即结算关卡；暂停和退出关卡不生成残影。
- 玩家位置、普通机关、可拾取物等临时状态随循环重置。
- 已激活的时间锚点等永久状态不会被重置。
- 暂停期间共享读秒、逻辑刻、记录、玩家、残影和机关全部停止更新。

这一方案牺牲了“随时结束本轮”的快捷性，但能换来统一记录长度、统一机关相位和更低的同步复杂度。玩家被驻留板捕获后，剩余时间会自然变成残影的有效停留时间，既提高容错率，也避免短记录残影提前结束。恒速巡行还消除了随意原地等待，使路线长度和时滞选择真正成为时间规划的一部分。

### 时间残影

残影能够：

- 按历史轨迹移动；
- 被驻留压力板捕获并保持激活；
- 触发感应器；
- 重复操作普通开关；
- 通过已经打开的门。

残影不能：

- 拾取能量钥匙；
- 推动箱子；
- 激活时间锚点；
- 完成出口结算；
- 阻挡玩家或其他残影；
- 被时滞射线重新施加减速或改变已记录路线。

### 多残影的代际与寿命

实现必须分两步进行：先完成并验收“单个残影 + 固定完整时间线”，再把容器扩展为多残影队列。未通过单残影确定性测试前，不得开发第三残影或代际机关。

MVP 的最终规则为：最多同时存在 2 个残影，每个残影会参加它创建后的 **2 个完整轮次**，只在轮次边界淘汰。设第 `n` 轮生成的残影为 `Eₙ`：

| 当前轮次 | 本轮开始时参与行动的残影 | 本轮结束后的变化 |
| --- | --- | --- |
| 第 1 轮 | 无 | 生成 `E₁` |
| 第 2 轮 | `E₁` | 生成 `E₂` |
| 第 3 轮 | `E₁ + E₂` | 生成 `E₃`，淘汰 `E₁` |
| 第 4 轮 | `E₂ + E₃` | 生成 `E₄`，淘汰 `E₂` |
| 第 5 轮 | `E₃ + E₄` | 继续按同一滑动窗口处理 |

因此，第 3 轮前两个残影都会行动；第 4 轮由第二、第三轮生成的残影行动。这个滑动窗口会迫使玩家考虑旧方案何时被覆盖，而不是无限累积残影。

#### 统一生命周期公式

残影的玩法寿命不单独按秒配置，而按完整轮次计算。关卡只配置残影容量/基础寿命 `L`，通常令二者相等；轮内时长仍使用该关统一的 `D = durationTicks`。设当前轮次为 `r`、残影来源轮次为 `s`：

```text
age = r - s
active = 1 <= age <= L
remainingRounds = L - age + 1
lifeProgress = clamp(((age - 1) * D + roundTick) / (L * D), 0, 1)
bodyAlpha = 0.82 - 0.32 * lifeProgress
```

- `active` 和 `remainingRounds` 决定玩法状态，残影只能在轮次边界生成或淘汰；
- `lifeProgress` 只用于透明度、轨迹和粒子表现，由共享 `roundTick` 推导，不是新的游戏计时器；
- `bodyAlpha` 从约 0.82 平滑下降到 0.50，正式淘汰前仍保持可辨识和可交互；
- 最后一轮读秒归零后，在统一的 `RESETTING` 过渡中将透明度从 0.50 降到 0，并释放光粒子，再移除残影；
- 关卡不能直接给每个残影配置不同秒数，否则会重新产生多套读秒和同步问题。

推荐配置为：第一关 `L = 1`，用于验收单残影；第二至第四关统一 `L = 2`；只有扩展挑战关才允许 `L = 3`。轮长 `D` 可随关卡调整，公式会自动等比例变化，但同一局中保持不变。

#### 代际视觉规则

不同轮次的残影必须同时通过颜色以外的方式区分，避免只靠色觉识别：

- 当前玩家：实色、高亮轮廓；
- 所有残影：保留稳定的来源轮次编号和来源色，不在中途交换身份；
- 较新的残影：按公式处于较高透明度，显示连续实线轨迹；
- 较旧的残影：按公式处于较低但仍清晰的透明度，显示虚线轨迹；
- 路线每隔 1 秒显示一个小刻度，交互时刻显示菱形节点，使玩家能比较两条路线的空间位置和到达时间；
- HUD 只显示残影的来源轮次和剩余存活**轮数**，不增加第二套秒级读秒。

多残影玩法不能只靠增加驻留板数量。第四关至少组合使用“代际感应板”“时空共振节点”和“共振中继器”；后续还可扩展轨迹织路、记忆锁定和第三残影，但仍保持所有参与者共用一个轮内时钟。

### 时滞射线与减速

- 玩家不能主动停止或变速后，时滞射线从单纯惩罚变为可规划的“节拍调节器”：是否选择经过、经过哪一段，会改变该条记录后续的到达时刻。
- 时滞射线可配置为常开或固定周期启停；穿过后将速度临时调整为基础速度的 50%–70%，持续 60–120 个逻辑刻，统一读秒仍正常推进，不会提前重置本轮。
- 具体模式、倍率与持续 tick 由关卡数据配置，同类效果不叠乘，只刷新到规定上限。标准解法需要借它校准相位时应使用常开或足够长的稳定窗口；短周期射线只用于进阶风险，不承担必需的精确校时。
- 射线启动前必须有颜色、声音或地面预警；角色受影响时显示清晰的状态图标和拖影，避免把环境变速误认为输入故障。
- 减速只在录制当下作用于当前玩家。玩家成为残影后，减速造成的慢速移动已经写入位置时间线，回放系统只读记录，不能再次套用减速，否则会产生二次减速和轨迹偏移。
- 关卡可通过轮长、路线距离、射线周期和减速强度调整难度，但这些参数在进入关卡时冻结，不能在同一局的不同轮次中变化。

### 高阶多残影玩法

多残影的核心不是“多几个角色”，而是让玩家编排不同轮次在**空间、时刻和寿命窗口**上的关系。

| 机制 | 玩法规则 | 为什么依赖时间残影 | 范围 |
| --- | --- | --- | --- |
| 时空共振 | 两个不同来源轮次的残影经过同一空间候选点，且经过时刻之差落入容差窗口，即锁存为本轮共振态 | 玩家要分别录制两条空间相交、时间接近且共振后仍有后续任务的路线 | MVP（第三/四关） |
| 共振中继 | 共振后，两条残影路线后半段成为能量通道；残影随后经过各自中继器才会传递能量 | 共振只是中间规则变化，能否完成取决于历史路线在交点之后如何继续 | MVP（第四关） |
| 轨迹织路 | 轨迹投影器把指定残影经过的特殊网格点亮为本轮临时道路，当前玩家只能沿过去亲手走出的路线通过 | 历史路线本身变成关卡地形，而不只是残影身体触发机关 | P1 首选扩展 |
| 逆相/顺序终端 | 要求较旧与较新残影按指定先后顺序经过，或沿相反方向同时通过 | 同时利用来源代际、方向和交互时刻 | P1 |
| 记忆锁定 | 允许指定残影额外存活 1 个完整轮次，但受容量限制时必须牺牲另一条记录 | 玩家选择保留哪段过去，改变默认滑动窗口 | P2 |

#### 共振判定与提示

可见轨迹可以保持 2–4 像素的细线，判定范围与绘制粗细完全分离：

- 每个当前玩家/残影具有不可见的圆形 `resonanceAura`，建议半径为 `0.30–0.40 × tileSize`；
- 每段历史轨迹具有不可见的胶囊形 `pathTolerance`，建议半径为 `0.08–0.12 × tileSize`；
- 当当前玩家中心到旧轨迹线段的最短距离不大于 `resonanceAura + pathTolerance` 时，只显示“可形成共振”的候选提示，不立即激活；
- 最近轨迹点同时保存原始逻辑刻。默认只要两条记录经过候选点的时差不超过 30–45 tick（60 Hz 下约 0.5–0.75 秒），下一轮两个残影经过时即可激活，不要求像素级、单帧级重合，也不要求持续站在一起；
- 普通状态只显示空间候选光环；按 `H` 后才显示“早/晚约 0.x 秒”，避免常驻数字干扰唯一读秒。

候选点随新时间线一起保存。下一轮第一个匹配残影经过时进入 `ARMED`，并保留 30–45 tick；第二个不同 `sourceRound` 的残影在窗口内经过同一候选点时进入 `LATCHED`。窗口超时则回到 `DORMANT`，不要求任何角色停留。当前玩家只负责录制和预览，不能与一个残影当场完成实际共振。

`LATCHED` 状态保持到当前轮结束，不会因残影离开而失效；下一轮恢复为 `DORMANT`，除非后续扩展明确使用时间锚点。

#### 共振的作用边界

共振不能直接通关，也不能只等价于“按下后出口打开”。MVP 中它用于开启本轮的“共振网络”：两条参与共振的残影路线后半段被点亮，只有它们随后分别经过对应的旧/新代际中继器，能量才会抵达核心。当前玩家还必须完成一段独立路线并操作核心终端，出口才可用。

高级关卡的共振建议发生在本轮约 35%–55% 的位置；之后必须保留残影中继、当前玩家移动和最终交互。准备轮中的每条记录也至少经过两个有意义的路线锚点，例如“校准候选点 + 代际中继器”，不得出现整轮只走到共振位置便等待结束的标准解法。

高阶关卡必须通过以下检验：如果把残影替换成从开局就存在的两个普通队友，谜题解法仍完全不变，那么它还不是合格的时间残影谜题，需要至少加入轨迹交汇、代际限制、整轮寿命覆盖或历史路线成路中的一种。

### 通关与评价

玩家满足关卡目标并到达出口后通关。MVP 记录循环次数、完成时间和提示使用情况；扩展版再据此计算 `S/A/B/C` 评级，并可加入时间碎片收集数。

## 五、关卡机关

| 机关 | 功能 | 残影能否触发 | 优先级 |
| --- | --- | --- | --- |
| 驻留压力板 | 进入后捕获角色至本轮结束，并持续保持对应门开启 | 可以 | MVP |
| 普通开关 | 切换目标机关状态 | 可以 | MVP |
| 脉冲开关 | 使目标机关开启数秒后自动复位 | 可以 | MVP |
| 时滞射线 | 按周期启停；改变当前玩家后续一段路线的速度与相位 | 不会再次影响回放中的残影 | MVP |
| 代际感应板 | 只接受配置指定的当前玩家、较新残影或较旧残影 | 仅匹配代际时可以 | MVP（第四关） |
| 时空共振节点 | 两条残影记录在空间接近且经过时差落入容差时激活，并锁存至本轮结束 | 必须由两个不同来源残影共同触发 | MVP（第三/四关） |
| 共振中继器 | 只在本轮共振态中接收对应代际残影的后续能量 | 可以 | MVP（第四关） |
| 出口终端 | 满足条件后完成关卡 | 不可以 | MVP |
| 能量钥匙 | 打开对应颜色的能量门 | 不可以 | 扩展 |
| 时间锚点 | 使指定状态跨循环保留 | 不可以 | 扩展 |
| 轨迹投影器 | 将残影走过的指定网格变为临时道路 | 使用残影轨迹 | P1 |
| 记忆锁定终端 | 延长指定残影一轮并触发容量取舍 | 使用残影交互 | P2 |
| 单向门 | 只允许从指定方向通过 | 可以通过 | 扩展 |

机关之间通过游戏事件连接。例如，驻留板只发布“捕获/激活/释放”事件，对应大门监听事件并改变状态，避免具体机关类直接互相引用。

## 六、关卡规划

8 天基线交付 5 个小型关卡，第 6 关仅在 MVP 通过功能门禁后开发。

| 关卡 | 名称 | 主要内容 | 教学目标 | 范围 |
| --- | --- | --- | --- | --- |
| 序章 | 时间苏醒 | 恒速巡行、路口排队转向、唯一读秒、自动切轮、出口 | 熟悉“只控制路线、不控制速度” | MVP |
| 第一关 | 留下的脚步 | 单残影、驻留压力板和门 | 理解“现在的动作会成为下一轮伙伴” | MVP |
| 第二关 | 即将褪去 | 两个残影、来源编号、整轮寿命、代际感应板 | 读懂新旧代际和滑动窗口 | MVP |
| 第三关 | 回声交点 | 时空共振候选、时滞射线、路径范围提示和时间容差 | 用路线长度与环境变速让两条历史轨迹对齐 | MVP |
| 第四关 | 时间核心 | 共振锁存、双中继、代际感应板、旧残影即将淘汰 | 共振后继续完成因果链，综合规划三轮 | MVP |
| 挑战关 | 时间织路 | 轨迹投影器、时间锚点；可选记忆锁定 | 让历史路线成为地形，并在 P2 中选择保留哪段过去 | P1（记忆锁为 P2） |

每关建议控制在 2–5 分钟；先使用色块和基础图形完成机制验证，再替换视觉素材。关卡不能依赖未完成的扩展机制来满足“五关可通关”的验收条件。

### 谜题教学曲线

关卡必须遵循“展示—练习—变化—组合”，不能在最终关突然加入未教学的新规则：

1. **序章展示规则**：用单一路口教会排队转向、不能主动停下、统一读秒和自动切轮，不要求复杂推理。
2. **第一关只教一个残影**：让驻留板自动停止角色，安全完成一次“录制—回放—协作”，先建立因果关系。
3. **第二关只增加代际**：通过编号、透明度和一块代际感应板说明旧残影会继续行动但会在整轮后淘汰。
4. **第三关加入时空交汇**：先演示“空间接近但时间差超过容差不会共振”，再让玩家通过选择长短路线或时滞射线调整相位。
5. **第四关组合旧知识**：不再增加规则，只组合恒速巡行、共享时钟、两代残影、共振锁存、中继和寿命覆盖，要求玩家先规划三轮再执行。

提示分三层提供：第一层只指出目标，第二层指出涉及哪两条时间线，第三层才显示推荐到达时刻或路线节点。使用提示会记录在成绩中，但不会改变本局计时规则。

### 第四关核心谜题草案

这一谜题用于验证玩法确实依赖“过去的自己”，而非普通双人机关：

| 轮次 | 玩家本轮计划 | 这段记录在后续的作用 |
| --- | --- | --- |
| 第 1 轮 | 沿路线 A 先经过一个相位标记，在约第 8 秒经过共振候选位置，之后到达旧代际中继器 | 第 3 轮成为较旧的 `E₁`，共振后负责旧中继 |
| 第 2 轮 | 沿路线 B 先完成方向机关，再穿过设计好的时滞段，使经过候选位置的时刻落在 `E₁` 的容差窗口内，之后到达新代际中继器 | 本轮结束后成为较新的 `E₂`，共振后负责新中继 |
| 第 3 轮 | `E₁` 与 `E₂` 的经过时差落入容差，共振锁存；二者继续巡行并分别点亮旧/新中继 | 当前玩家完成第三条路线，在双中继供能后操作核心终端；本轮结束后 `E₁` 将淘汰 |

第 2 轮中当前玩家靠近 `E₁` 的旧轨迹只会得到空间/时差提示，不会当场激活；要到第 3 轮两条记录都成为残影后才真正共振。共振发生后还要由两条路线的后半段完成中继，并由当前玩家操作核心，这一“先对齐、再兑现、最后接力”是最终关的主要思考点。

每个高级谜题设计完成后都要画一张“轮次 × 秒数 × 角色”的纸面时间表，并让未参与设计的成员试玩。如果解法依赖精确到单帧操作、只能靠反复碰运气，或无法从画面判断失败原因，就应扩大判定半径/时间容差或减少一个条件。

### 轮长与任务密度

高级关不能凭感觉随意设定 20 秒，也不能让玩家在一个循环里只完成一次很短的共振准备。先按无失误路线测量关键动作时间 `P`，再使用以下初始值并通过试玩校正：

```text
roundDuration = P + max(2 秒, 0.25 × P)
```

- `P` 必须包含恒速移动、设计要求的时滞段、交互缓冲和驻留前的全部任务，但不包含故意撞墙或不存在的自由等待；
- 共振候选建议位于本轮 35%–55%，两个中继位于 60%–80%，当前玩家最终操作位于 80%–95%；
- 第三、四关的每条准备记录至少包含两个分离的路线锚点，共振不能是该轮唯一动作或路线终点；
- 如果熟练玩家在 60% 轮长前已经无事可做，应缩短轮长或重新安排后续中继，而不是增加空等；
- 至少邀请 3 名未参与设计者试玩：理解解法后的成功率应主要取决于路线选择，而不是单帧转向；时间容差和输入缓冲可据此调整。

### 视觉与渲染方向：暗调简约几何

视觉气质参考《纪念碑谷》的简洁几何、清晰轮廓、留白和柔和色彩关系，但必须使用原创角色、场景构图、图标、配色与动画，不复制其关卡、建筑、角色或素材。本周期保持正交俯视的逻辑坐标和碰撞，只通过轻微侧面偏移、长阴影和分层色块营造 2.5D 深度，不实现真正的等距投影、非欧几里得道路或视错觉碰撞。

#### 建议色板

| 用途 | 建议颜色 | 说明 |
| --- | --- | --- |
| 深色背景 | `#0C1018` | 接近黑蓝，降低视觉噪声 |
| 建筑顶面 | `#2A3040` | 低饱和蓝灰 |
| 建筑侧面/阴影 | `#171C28` | 与逻辑墙体形成轻微高度差 |
| 当前玩家 | `#F4E7C5` | 暖象牙色，始终最醒目 |
| 新残影/来源色 A | `#65D6D2` | 冷青色，透明度由生命周期公式控制 |
| 旧残影/来源色 B | `#A88BE8` | 柔紫色，同时使用虚线和编号区分 |
| 可交互/目标 | `#E6B85C` | 暖金色，用于机关边缘和目标反馈 |
| 时滞危险 | `#D85C7A` | 玫红色，启动前必须先显示低亮预警 |
| 正文与 HUD | `#D9DFEA` | 保持暗背景上的可读性 |

色板只是团队原创视觉的起点，可以统一调整，但交互状态之间必须保持足够明度差，不能只通过色相表达功能。

#### 画面分层

1. 深色纯色或极轻渐变背景；
2. 地面和墙体几何块，使用 4–8 像素侧面偏移与单方向软阴影；
3. 门、感应板、共振点和时滞射线；
4. 预计算的残影路径、每秒刻度和交互节点；
5. 当前玩家、不同代际残影及高亮轮廓；
6. 共振、命中、轮次切换和残影消散粒子；
7. 始终清晰、不随世界缩放的 HUD 与唯一读秒。

#### 残影渲染与消散

- 新残影同样从半透明开始，并按 `lifeProgress` 连续降低透明度；较新/较旧的差异来自生命周期阶段，不需要额外计时器。
- 轨迹由录制帧降采样生成，每 3–6 个逻辑刻取点，并缓存为折线或离屏画布；不能每帧重复处理全部原始帧。
- 实线/虚线、来源编号、每秒小刻度和交互菱形必须比粒子更优先，先保证玩家能读懂路线。
- 即将淘汰的残影在最后一轮仍保持最低 0.50 左右的不透明度；读秒归零后进入 300–500 毫秒的轮次过渡，再用 20–40 个小菱形/光点完成消散。
- 粒子只做简单位置、速度、寿命和透明度更新，可复用对象；不做逐像素溶解、复杂模糊或实时着色器。

#### 实现难度与取舍

| 效果 | 相对难度 | 粗略工作量 | 本周期建议 |
| --- | --- | --- | --- |
| 生命周期透明度与代际描边 | 低 | 1–2 小时 | 必做 |
| 降采样轨迹、虚线和时间节点 | 中 | 3–5 小时 | 必做 |
| 简单 Canvas 粒子消散 | 中 | 3–6 小时 | MVP 稳定后加入 |
| 暗调几何块、侧面和统一 CSS | 中 | 4–8 小时 | 先做统一模板，再复用到全部关卡 |
| 逐像素溶解、复杂光照或真正视错觉 | 高 | 2 天以上且牵连架构 | 本周期不做 |

上述估时从可运行的基础渲染开始计算。若工期压缩为 7 天，保留透明度、轨迹和几何色块，消散粒子缩减为一次简单光点爆散；任何特效都不能阻塞残影回放和五关验收。

### 架构原则

- 状态模式：管理启动、菜单、游戏、暂停、重置和结算状态。
- 记录/命令思想：保存每轮行动与离散交互事件。
- 快照模式：恢复关卡临时状态，同时保留明确的永久状态。
- 工厂模式：从关卡数据创建实体和机关。
- 观察者/事件模式：连接驻留板、开关、共振网络、大门和出口。
- 数据驱动：关卡参数尽量从 JSON 加载，减少硬编码。
- 单向依赖：UI 不直接修改回放数据，机关不直接控制具体 UI。
- 可测试核心：计时、碰撞、记录、重置和机关状态尽量不依赖 JavaFX UI 对象。

### 游戏状态建议

```text
BOOT -> MENU -> LEVEL_SELECT -> READY -> PLAYING -> RESETTING -> READY
                                  |         |          |
                                  |         v          v
                                  +------> PAUSED    RESULT
```

具体类、接口、依赖方向和线程约束必须写入 `TECHNICAL_GUIDE.md` 并经全组确认后实现。

## 九、时间回放方案

逻辑层采用固定更新频率，建议以每秒 60 个逻辑刻为基准；20 秒关卡对应 1200 个逻辑刻。渲染可以波动，但一次更新、记录与回放都以逻辑刻为准。

每个逻辑刻记录一条玩家状态：

```java
public record PlayerFrame(
        long tick,
        double x,
        double y,
        Direction direction,
        boolean interacting,
        MovementState movementState,
        AnimationState animationState
) {}
```

一轮结束后，恰好 `durationTicks` 条 `PlayerFrame` 被封装为一个带来源轮次的 `TimelineRecording`。本轮的所有 `Echo` 直接使用共享的 `roundTick` 读取对应帧，不维护自己的播放时钟或秒级剩余时间。

项目采用“位置快照 + 交互事件”的混合记录方式，不只重新模拟键盘输入：

- 连续状态：每个逻辑刻的位置、朝向以及 `CRUISING`、`SLOWED`、`ANCHORED` 移动状态；
- 离散事件：在指定逻辑刻发生的排队转向、交互、驻留捕获或开关操作；
- 固定长度：松开方向键不会停止记录；只有被驻留板捕获后才写入静止帧，所有记录在本轮最后一个逻辑刻同时结束；
- 同步回放：全部残影以同一个 `roundTick` 索引各自时间线，禁止独立累加播放时间；
- 减速回放：时滞效果只改变当前玩家并写入记录；残影只播放结果，不重新执行碰撞或减速计算；
- 暂停：不增加逻辑刻，不写入新帧；
- 掉帧：补做有限次数的固定更新，但不能跳过或重复记录逻辑刻；严重掉帧时宁可游戏时间短暂变慢，也不能让回放索引漂移；
- 轮次边界：冻结第 `durationTicks` 个状态，封装记录并加入残影队列，按整轮寿命淘汰旧残影，恢复临时快照，将 `roundTick` 归零后同时启动所有角色；
- 轮前准备：`READY` 阶段不增加 `roundTick`、不写帧，只收集初始方向；进入 `PLAYING` 后当前玩家与所有残影同时启动；
- 参数冻结：`baseSpeed`、`durationTicks`、残影上限、存活轮数、时滞倍率、共振容差和机关周期在进入关卡时确定，本局中途不得改变。

世界状态分为：

- 临时状态：玩家位置、排队方向、普通门、驻留板、时滞射线周期、当前减速状态、共振锁存和可拾取物等，每轮重置；
- 永久状态：已激活时间锚点所声明的状态，在当前关卡内跨循环保留；
- 会话状态：共享轮长、残影队列、来源轮次、剩余存活轮数、循环次数和提示记录，直到离开或重开关卡才清空。

## 十五、测试策略

### 自动化测试重点

- 每一轮记录都恰好包含 `durationTicks` 个连续逻辑刻，包括末段静止状态；
- 所有残影始终使用同一个 `roundTick`，不同渲染帧率下得到相同位置和交互结果；
- `READY` 阶段不推进逻辑刻，进入 `PLAYING` 后所有角色从预选方向同时启动；
- 松开方向键后速度仍为 `baseSpeed`；路口按既定优先级转向，正面遇墙不会使角色停留；
- 驻留板是正常轮次中唯一可将角色固定至本轮结束的基础机关，6–10 tick 交互缓冲不会重复触发；
- 暂停期间不增加逻辑刻、不记录帧、不消耗共享倒计时；
- 正常游戏中不存在提前截断本轮的输入路径，读秒归零只触发一次原子化轮次切换；
- 第 3 轮为 `E₁ + E₂`，第 4 轮为 `E₂ + E₃`，旧残影只在边界淘汰；
- `age`、`remainingRounds`、`lifeProgress` 和透明度公式在首刻、轮次边界与末刻结果正确；
- 最早残影移除后，其驻留板/开关占用状态被正确释放；
- 时滞减速只影响录制时的当前玩家，残影回放时不会再次减速或偏离；
- 代际感应板只响应配置指定的当前玩家、较新残影或较旧残影；
- 共振候选判定使用不可见范围而非轨迹绘制宽度；容差内的两个不同来源残影可触发，当前玩家加一个残影不能提前触发；
- 第一个残影进入后状态为 `ARMED`；同来源不能完成共振，窗口超时回到 `DORMANT`，不同来源在窗口内进入 `LATCHED`；
- 共振一旦激活便锁存到本轮结束，离开候选范围不会失效，下一轮会正常复位；
- 共振本身不能打开出口；只有共振后的旧/新中继均收到能量，且当前玩家操作核心后才能结算；
- 轨迹降采样、透明度和消散粒子不能修改任何玩法状态或回放数据；
- 普通状态会重置，永久状态只在规则允许时保留；
- 玩家不能穿过墙壁或关闭的大门；
- 存档不存在、损坏或字段缺失时使用安全默认值。

### 手工与集成测试重点

- 从主菜单到 5 个关卡再到结算的完整流程；
- 通关、重新开始关卡和返回菜单后不残留旧状态；
- HUD 只出现一个所有角色共享的轮内读秒，轮次切换时没有视觉或逻辑错拍；
- `WASD`、方向键、`E`、`H`、`Esc` 行为正确；松键不会停止，游戏中没有主动变速、冲刺或提前结束本轮的按键；
- 不同轮长和时滞参数只在进入关卡时生效，本局中途保持不变；
- 目标电脑的 JDK 17、窗口缩放、音量和文件写入表现；
- 连续运行和多次轮次切换后无明显卡顿或内存持续增长；
- 暗调场景中，残影颜色、透明度、来源编号、轨迹样式和交互节点足以区分当前玩家与不同代际残影；
- 时滞射线有明确预警；玩家能够看懂哪条路线利用它调整相位、哪条路线应当避开，减速不会造成输入失控。
- 未参与关卡设计的成员能在分层提示帮助下理解第四关失败原因，而不是靠随机试错通关。

缺陷按“阻塞 / 高 / 中 / 低”分级。第 7 天起只修阻塞和高优先级缺陷；中低优先级只有在不影响回归时处理。

## 十六、验收标准

项目交付前必须满足：

1. 在 JDK 17 环境中能够通过 Maven 构建、测试和运行。
2. 从主菜单到关卡结算的完整流程无阻塞性错误。
3. 至少 5 个 MVP 关卡可以正常通关。
4. 单残影基础先独立通过验收，随后至少 2 个不同代际残影可按共享时钟稳定同步回放。
5. 每条记录长度等于关卡固定轮长；不存在提前截止，暂停、自动轮次切换和场景切换不会破坏记录状态。
6. 设置、关卡进度和最好成绩可以本地保存，损坏时可安全恢复。
7. 核心逻辑具有自动化测试，主要功能有手工测试记录。
8. 项目包含源码、资源、运行说明、技术指南、测试报告和答辩材料。
9. 五名成员都完成 5 个板块的影子体验，并能解释自己主责模块与至少一个协作模块。
10. 所有 AI 生成代码均可追溯到单模块任务卡及对应验证记录。
11. 第四关必须实际使用时空共振和代际寿命；将残影替换为两个开局常驻角色后，原解法不能继续成立。
12. 暗调几何画面保持原创，唯一读秒、机关状态、不同代际和关键路线在目标显示器上清晰可读。
13. 玩家在 `PLAYING` 中不能自由停止或主动改变基础速度；路线、时滞和驻留规则在当前玩家与回放残影之间表现一致。
14. 第四关的共振只是中间锁存状态，之后仍需两个残影完成中继、当前玩家完成独立路线并操作核心。

## 十七、答辩展示重点

推荐演示顺序：

1. 展示玩家松开方向键后仍恒速巡行，并在路口提前排队转向。
2. 展示单人无法直接通过的双驻留板关卡；第一轮进入一侧驻留板，等待唯一读秒归零和自动切轮。
3. 展示残影从逻辑刻 0 开始，按完整固定时间线重复上一轮行动。
4. 进入第三轮，展示新旧两个残影同时行动，以及编号、透明度和轨迹样式的代际差异。
5. 展示一条记录经过时滞射线改变相位，并在下一轮与另一条记录进入共振容差。
6. 展示共振锁存后两个残影继续完成中继，当前玩家再操作核心通关。
7. 用短图示说明共享逻辑刻、混合记录、整轮寿命、状态快照和事件系统。
8. 展示不同帧率下的回放测试、模块分工、轮岗记录和本地成绩。
9. 若 P1 已完成，再展示第三残影、评级或时间锚点，不影响主线演示。

“第一次生成残影并与过去的自己开门”负责让观众立刻看懂规则；“第三轮两个不同代际残影进入共振容差、继续完成双中继并启动时间核心”负责证明玩法创新。两段演示都必须在目标电脑上完整彩排，并准备无需扩展功能的稳定备用关卡。

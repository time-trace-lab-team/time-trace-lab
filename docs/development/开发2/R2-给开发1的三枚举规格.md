## 附录：C1 §2 缺陷 —— `stepOnce()` 仍为 `void`（需返工）

> 此项与上面的枚举规格**独立**，可分开排期；但同属开发 1，一并提交以减少往返。

### 现象

| 文件 | 现状 | 违反 |
| --- | --- | --- |
| `core/TickUpdatePort.java` | `void stepOnce()` | C1 §2 冻结的 `TickStepResult stepOnce()` |
| `core/FixedStepLoop.java` 第 38–40 行 | `for (int i = 0; i < steps; i++) updatePort.stepOnce();` 无条件循环 | C1 §2「收到 `ROUND_END` 或 `NO_ADVANCE` 必须立即停止剩余步数」 |

### 危害

`ROUND_END` 后再调一次 `stepOnce()`，等于把第 `D-1` 刻**原样跑第二遍**：
输入被消费两次、该刻被记录两条、残影寿命推进两格 —— 直接破坏 C1 §3 的推论「有效记录恰好 `D` 条、`frame.tick` 等于列表索引」。

**关键点**：`RoundClock.advance()` 返回 `ROUND_END` 时，其内部状态**完全没变**
（`phase()` 仍是 `PLAYING`、`roundTick()` 仍是 `D-1`、`currentRound()` 不自增）。
也就是说「已到轮末」**只能通过 `advance()` 的返回值观测，查任何 getter 都看不出来** —— 所以 `void` 是致命的，不是"暂时不方便"。

### 目前为何尚未爆

`TickUpdatePort` **还没有实现方**（开发 2 在 R3 才接线）。R3 一接线立刻出问题。

### 建议修法

```java
for (int i = 0; i < steps; i++) {
    if (port.stepOnce() != TickStepResult.ADVANCED) {
        break;   // NO_ADVANCE 或 ROUND_END：立即停止
    }
}
// 剩余 steps 直接丢弃，不回填 accumulator、不带入下一帧
```

### ⚠️ 修复前需 PM 先裁 C1 §5.1

`TickStepResult` 与既有的 `replay.AdvanceResult` 三值**逐字相同**（`NO_ADVANCE / ADVANCED / ROUND_END`，21 条测试在用），
C1 §5.1 尚未裁决归属：

| 方案 | 放置 | 影响 |
| --- | --- | --- |
| A（开发 2 推荐） | 新建 `core.TickStepResult`，删除 `replay.AdvanceResult` | 开发 2 需改 `RoundClock` 签名与 13 条测试（独立卡） |
| B | 保留 `replay.AdvanceResult`，`core` import 它 | 引入 `core → replay`，与 C1 §1.1 方向相反 |

**请开发 1 先不要擅自新建 `core.TickStepResult`** —— 若 PM 选 B，那个类就得删。
可先按三值语义写好 `FixedStepLoop` 的分支判断，类型名留占位。

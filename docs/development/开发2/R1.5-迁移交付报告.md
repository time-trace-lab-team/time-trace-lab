## 6. 最终 `RoundClock` 对外接口（开发 1 据此接入）

```java
package org.example.timeloop.replay;

import org.example.timeloop.core.GamePhase;

public final class RoundClock {

    /** @param durationTicks 每轮固定时长（tick），范围 [1, ∞)，进关冻结 */
    /** @param maxRounds     本关最大轮数，范围 [1, ∞)，进关冻结 */
    public RoundClock(int durationTicks, int maxRounds)

    /** 合法转移；非法转移抛 IllegalStateException */
    public void transition(GamePhase to)

    /** NO_ADVANCE（冻结阶段）/ ADVANCED（推进一刻）/ ROUND_END（已在末刻） */
    public AdvanceResult advance()

    public GamePhase phase()          // 当前阶段，权威值
    public long roundTick()           // 0 .. durationTicks-1
    public int currentRound()
    public int durationTicks()
    public int maxRounds()
    public boolean isPlaying()        // phase == GamePhase.PLAYING
    public TickContext toContext()    // 不可变快照，字段全 final
}
```

### 6.1 `LEGAL` 转移表（10 组边，逐条照搬）

```text
BOOT          -> MENU
MENU          -> LEVEL_SELECT
LEVEL_SELECT  -> TUTORIAL, READY
TUTORIAL      -> READY
READY         -> PLAYING, PAUSED, TUTORIAL, LEVEL_SELECT
PLAYING       -> PAUSED, RESULT, RESETTING, FAILED
PAUSED        -> PLAYING, READY, LEVEL_SELECT
RESETTING     -> READY
RESULT        -> MENU, LEVEL_SELECT
FAILED        -> READY, LEVEL_SELECT
```

### 6.2 行为保证（供开发 1 依赖）

- `durationTicks` / `maxRounds` 为 `final`，进关冻结，本局不可改
- **仅 `PLAYING` 推进 `roundTick`**；其余 9 个阶段 `advance()` 恒返回 `NO_ADVANCE`
- `roundTick` 严格在 `0 .. D-1`；到达 `D-1` 后再推进恒返回 `ROUND_END`，**不递增、不切轮、不存在索引 `D`**
- `ROUND_END` 之后**内部状态完全不变**：`phase()` 仍 `PLAYING`、`roundTick()` 仍 `D-1`、`currentRound()` 不自增
  → **「已到轮末」只能通过 `advance()` 的返回值观测，查任何 getter 都看不出来**
- `ROUND_END` 后**不会自动切到** `RESETTING` / `RESULT` / `FAILED`；轮次事务由上层发起
- 转移副作用：
  - `READY`：来自 `RESETTING` 则 `currentRound++`，否则置 1；`roundTick = 0`
  - `PLAYING`：来自 `READY` 则 `roundTick = 0`，来自 `PAUSED` 则保留
  - `RESETTING` / `FAILED`：`maxRounds` 守卫异常不变
  - `BOOT` / `MENU` / `LEVEL_SELECT` / `TUTORIAL`：重置为全新会话
  - `PAUSED` / `RESULT`：保留 `roundTick`
- 非法转移抛 `IllegalStateException`，异常信息含 `from -> to`

## 7. 给开发 1 的两点后续提醒（本次迁移未涉及，但接入前必须解决）

### 7.1 🔴 `FixedStepLoop` 目前没有轮末停止机制

`FixedStepLoop.onAnimationFrame` 当前实现：

```java
int steps = clock.advance(nanoTime, phase);
for (int i = 0; i < steps; i++) {
    updatePort.stepOnce();
}
```

`TickUpdatePort.stepOnce()` 仍是 `void`。一旦接入 `RoundClock`，**一帧补算多刻且跨轮末时，循环不会停止**，会把第 `D-1` 刻重复执行多次（输入消费两次、该刻记录多条），破坏「有效记录恰好 D 条」。

C1 §2 要求的是：仅在 `ADVANCED` 时继续补算，收到 `ROUND_END` 或 `NO_ADVANCE` 立即停止，剩余额度丢弃。
**放置位置（`core.TickStepResult` 还是沿用 `replay.AdvanceResult`）属 C1 §5.1 未裁决项，需 PM 拍板后再动。** 详见 `C1-接口答复-Tick顺序与轮末结果.md`。

### 7.2 🟡 单 tick 顺序请对齐 C1 §3 的 7 步

接入时 `stepOnce()` 内部应为：读 `TickContext` → 消费输入 → 更新玩家/机关/残影 → 排序事件 → 记录 tick 末状态 → 生成只读渲染快照 → `RoundClock.advance()`。
其中**渲染快照必须在 `advance()` 之前**生成；补算多刻时每次都要重新读 `TickContext`。

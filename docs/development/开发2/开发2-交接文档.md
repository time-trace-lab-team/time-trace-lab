## 3. 核心类型与语义

### 3.1 `TickContext`（R0，不可变 record）

```java
public record TickContext(long roundTick, int durationTicks, int currentRound, int maxRounds)
```

- 字段语义：`roundTick` 轮内第几刻、`durationTicks` 本轮总共多少刻、`currentRound` 当前第几轮、`maxRounds` 最多几轮。
- 构造校验（非法即抛 `IllegalArgumentException`）：
  - `durationTicks >= 1`；`maxRounds >= 1`；
  - `currentRound` 于 `[1, maxRounds]`；
  - `roundTick` 于 `[0, durationTicks-1]`。
- 派生方法：`isLastTick()` — 是否为本轮最后一帧（`roundTick == durationTicks - 1`）。
- 只读：字段全 `final`，无 setter、无可变集合写入口。

### 3.2 `RoundPhase`（R1，开发 2 自己的阶段枚举）

```java
public enum RoundPhase { BOOT, MENU, LEVEL_SELECT, TUTORIAL, READY, PLAYING, PAUSED, RESETTING, RESULT, FAILED }
```

- `advances()` 仅 `PLAYING` 返回 `true`；其余为冻结阶段（推进 `roundTick` 时返回 `NO_ADVANCE`）。
- **注意**：这是开发 2 自己的一套阶段表示，**独立于** 开发 1 的 `core/GamePhase`（那边只有 BOOT/READY/PLAYING/PAUSED）。现阶段两套并存，最终收敛为单一 `GamePhase` 需项目经理拍板（见第 7 节）。

### 3.3 `AdvanceResult`（R1）

```java
public enum AdvanceResult { NO_ADVANCE, ADVANCED, ROUND_END }
```

- `NO_ADVANCE`：冻结阶段零推进（TUTORIAL/READY/PAUSED/RESETTING/RESULT/FAILED）。
- `ADVANCED`：推进到下一逻辑刻。
- `ROUND_END`：到达本轮最后一帧（`D-1`），不再存在下一帧，发出轮末信号。

### 3.4 `RoundClock`（R1，唯一 `roundTick` 权威值）

```java
public final class RoundClock {
    public RoundClock(int durationTicks, int maxRounds)          // 参数进关冻结
    public void transition(RoundPhase to)                        // 非法转移抛 IllegalStateException
    public AdvanceResult advance()                               // 一次推进一逻辑刻
    public RoundPhase phase()
    public long roundTick()
    public int currentRound()
    public int durationTicks()
    public int maxRounds()
    public boolean isPlaying()
    public TickContext toContext()                               // 不可变共享快照
}
```

**关键不变量**
- `durationTicks` / `maxRounds` 为 `final`，进关冻结，本局不可改。
- `advance()` 仅在 `PLAYING` 真正推进；`roundTick` 严格 `0..D-1`，**不存在索引 `D`**；到 `D-1` 再推进返回 `ROUND_END`，**绝不静默跳到下一轮**。
- 一次 `advance()` 只推进一个逻辑刻，**不会跃迁/跳到未来**；与开发 1“宁可慢也不欠时间债”的补帧策略相容。
- 非法阶段转移明确失败（`IllegalStateException`）。

**合法阶段转移（`transition` 允许的边）**

| 前阶段 | 可到的阶段 |
| --- | --- |
| BOOT | MENU |
| MENU | LEVEL_SELECT |
| LEVEL_SELECT | TUTORIAL、READY |
| TUTORIAL | READY |
| READY | PLAYING、PAUSED、TUTORIAL、LEVEL_SELECT |
| PLAYING | PAUSED、RESULT、RESETTING、FAILED |
| PAUSED | PLAYING、READY、LEVEL_SELECT |
| RESETTING | READY |
| RESULT | MENU、LEVEL_SELECT |
| FAILED | READY、LEVEL_SELECT |

**转移副作用（`RoundClock` 内部）**
- `READY`：从 `RESETTING` 进入则 `currentRound++`（仅非最终轮，否则抛异常）；否则回第 1 轮；`roundTick=0`。
- `PLAYING`：从 `READY` 进入则 `roundTick=0`（新一轮开始）；从 `PAUSED` 恢复则保留 `roundTick`（续玩）。
- `RESETTING`：仅当 `currentRound < maxRounds`，保留 `roundTick`（`D-1` 末刻冻结）。
- `FAILED`：仅当 `currentRound == maxRounds`，保留 `roundTick`。
- `BOOT/MENU/LEVEL_SELECT/TUTORIAL`：重置为全新会话（`currentRound=1`, `roundTick=0`）。
- `PAUSED` / `RESULT`：保留 `roundTick`。

## 5. 已向开发 1 确认的 C1 接口结论（重要，开发 1 在等）

开发 1 用 `TickContext` 做 C1（固定步长接游戏循环），逐条确认结果如下，**已达成一致的约定**：

1. 当前第几刻从 0 开始数 —— **对**。
2. 范围 0 到总刻数减一（60 Hz × 20 s = 1200 → 0..1199，共 1200 刻）—— **对**。
3. 数到最后一刻后“封装记录、生成残影、复位机关、开新一轮”整套交接 —— **责任归开发 2，但目前 R1 只实现到“发出轮末信号（`ROUND_END`）并停在 `D-1`”**；完整事务属 R3/R5，尚未实现。
4. 时间一律整数刻、不用秒/小数 —— **对**（`roundTick` 为 long，其余为 int）。
5. 一轮多长、最多几轮进关冻结、中途不可改 —— **对**（`durationTicks`/`maxRounds` 为 `final`）。
6. “当前阶段（游戏中/暂停中）”的值 —— **由开发 2 给，但现阶段给的是 `replay.RoundPhase`，不是 `core.GamePhase`**（读 `RoundClock.phase()` 或 `isPlaying()`）。
7. 一帧补跑多刻、正好跨本轮结束 —— **设计上由开发 2 在同一次更新里切完，但目前尚未实现**；当前约定：开发 1 见到 `ROUND_END` 就不要再对 clock 取后续刻、交还开发 2。

**当前对开发 1 的代码约定**
- 每逻辑刻调用一次 `clock.advance()`（或先读 `phase()`/`isPlaying()` 决定是否走时间）。
- 返回值 `ADVANCED`（推进 1 刻）/ `NO_ADVANCE`（冻结零推进）/ `ROUND_END`（本轮终点，交还控制）。
- 开发 1 只向 `RoundClock` 提供“走一步”的请求，时间推进与轮次切换归开发 2。

**关于开发 1 修复时钟的两点**：开发 2 的 `advance()` 一次一步、离散推进，`roundTick` 不可能跳到未来；与“宁可慢不欠时间债”及“时间源回退修复”相容。实现 R3 轮次事务时，会专门补“一帧补跑多刻且跨轮末、同一次更新切完、`roundTick` 不跳”的确定性测试。

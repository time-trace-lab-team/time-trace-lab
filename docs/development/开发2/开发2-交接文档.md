## 4. 核心类型速查

> 完整语义见 `开发2-时间与状态系统-技术指南.md` §3；这里只给接手人最短的"这玩意干嘛用"。

### 4.1 `TickContext`（record，不可变）
`(long roundTick, int durationTicks, int currentRound, int maxRounds)`。
构造校验全部范围；`isLastTick()` 判末刻。**所有 actor 共享它的只读快照。**

### 4.2 `RoundClock`（唯一时间权威）
- `advance()` 返回 `core.TickStepResult`：仅 `PLAYING` 推进，`D-1` 后再推返回 `ROUND_END`，
  **不递增、不切轮、不存在索引 D**（返回值是唯一能观测"已到轮末"的通道）。
- `transition(GamePhase)`：非法转移抛 `IllegalStateException`，10 组 `LEGAL` 边。
- `toContext()`：给所有 actor 的不可变共享快照。
- ⚠️ 不产生真实时间：纳秒累加/补帧是开发 1 的 `FixedStepClock`。

### 4.3 `PlayerFrame`（record，不可变）
`(long tick, double x, double y, Direction direction, boolean interacting,
  MovementState movementState, ActorPhase actorPhase, int actorPhaseTicksRemaining,
  AnimationState animationState)`。
- `tick` 取 `long`，在记录中必须等于列表索引。
- README 的 `boolean phaseDodging` 由 `actorPhase` 表达，`isPhaseDodging()` 派生
  （`PHASED ⇔ true`，且保留 `RECOVERING` 冷却信息）。
- `interacting` 是**边沿**语义（本刻是否触发交互），对应 `PlayerKinematics.interactionTriggered`。

### 4.4 `TimelineRecording`（定长缓冲）
- `record(frame)` 强制校验 `frame.tick() == 已写入帧数`：缺/重/乱序一律抛异常。
- 满 `durationTicks` 才能 `seal()`，且只一次；封后拒绝写入。
- `frameAt(tick)` / `frames()`（只读副本）。未满缓冲由边界方法丢弃，不封装。

### 4.5 `EchoState`（单残影）
- `of(recording)` 只接受**已封装满长记录**（否则抛异常，不用末帧补齐）。
- `frameAt(roundTick)` 按共享 roundTick 直接索引 —— **无独立时钟、不重算任何逻辑**。

### 4.6 `EchoLifetime`（寿命公式，README 原样）
- 输入 `(sourceRound, L, durationTicks, currentRound, roundTick)`，
  输出 `age / active / remainingRounds / lifeProgress / bodyAlpha`。
- 推荐 `of(sourceRound, L, TickContext)` 工厂：轮次/刻从共享时钟派生，**禁止自建第二套计数**。
- `isLastEffectiveRound()` / `shouldDisappearAtRoundEnd()` 供 HUD 与消散判定。

### 4.7 `EchoQueue`（滑动窗口，容量 2）
- `addOnRoundEnd(echo, nextRound)`：加入本轮残影并按 `nextRound - s > L` 在边界淘汰。
- `activeEchoes(currentRound)`：按 sourceRound 升序（较旧在前）。
- `lifetimes(TickContext)`：每个活跃残影的只读寿命视图。
- `clear()`：完整重开清空。

### 4.8 `RecordingSession`（轮末事务 + 四种边界）
聚合 `RoundClock` + 当前缓冲 + `EchoQueue`：
- `beginRound()`：开新缓冲（来源轮次 = 时钟当前轮）。
- `recordFrame(frame)`：仅 `PLAYING` 接受。
- `completeNormalRound(Runnable restorer)`：封装→生成残影→入队淘汰→恢复机关→`RESETTING→READY`→开新缓冲。
- `failFinalRound()`：仅最终轮，丢弃不生成，进 `FAILED`。
- `completeGoal()`：丢弃未满缓冲，进 `RESULT`。
- `restartFromFirstRound(Runnable restorer)`：清缓冲 + 清残影 + 初始快照，回第 1 轮 `READY`。
- ⚠️ 机关快照恢复以**注入 Runnable 占位**（照 `OrderedTickUpdatePort` 的回调模式），
  等开发 3 冻结 `MechanismSnapshot` 后替换为真端口。

## 8. 环境与踩过的坑（⚠️ 接手人必读，别的文档没有）

| 项 | 值 / 做法 |
| --- | --- |
| JDK | `D:\1\jdk`（OpenJDK 17.0.20.1）；**无全局 JAVA_HOME/PATH**，每个新终端先设：`export JAVA_HOME="D:/1/jdk"; export PATH="$JAVA_HOME/bin:$PATH"` |
| Maven | 仓库 Wrapper 3.9.11，可用 `-o` 离线；**不要跑 `mvnw.cmd -o clean`**（clean 插件无本地缓存会失败），干净重编请手动 `rm -rf target` |
| 网络 | 本机代理 `127.0.0.1:7897` 可能没开；连不上就直连：`git -c http.proxy= -c https.proxy= <cmd>` |
| Git 斜杠分支坑 | `feature/*` 分支的 ref 文件在 switch/commit/push/reset 后**会静默丢失**（`git branch -vv` 看不到、`rev-parse HEAD` 报错、工作区被当成全新文件）。恢复：`mkdir -p .git/refs/heads/feature` 后，从 `.git/logs/HEAD` 末行取 SHA 手写进 ref 文件。**每个 git 操作后必须 `git rev-parse HEAD` 复核** |
| **Git `rm` 事故** | 在 HEAD 损坏状态下执行 `git rm <file>` 会**删掉整个 `src/`**！**永远用 `rm` + `git add`，不用 `git rm`**；`git add` 尽量显式列文件，别用 `-A` |
| 认证 | HTTPS 远端首次 push 需 GCM 弹窗授权（本机终端） |

## 4. 核心类型速查

> 完整语义见 `开发2-时间与状态系统-技术指南.md` §3。

### 4.1 `TickContext`（record，不可变）
`(long roundTick, int durationTicks, int currentRound, int maxRounds)`。  
构造校验全部范围；`isLastTick()` 判末刻。**所有 actor 共享它的只读快照。**

### 4.2 `RoundClock`（唯一时间权威）
- `advance()` 返回 `core.TickStepResult`：仅 `PLAYING` 推进，`D-1` 后再推返回 `ROUND_END`，**不存在索引 D**。
- `transition(GamePhase)`：非法转移抛 `IllegalStateException`，10 组合法边。
- `toContext()`：给所有 actor 的不可变共享快照。
- ⚠️ 不产生真实时间：纳秒累加/补帧是开发 1 的 `FixedStepClock`。

### 4.3 `PlayerFrame`（record，不可变）
`(long tick, double x, double y, Direction direction, boolean interacting, MovementState movementState, ActorPhase actorPhase, int actorPhaseTicksRemaining, AnimationState animationState)`。
- `tick` 取 `long`，在记录中必须等于列表索引。
- `isPhaseDodging()` 派生：`PHASED ⇔ true`，保留 `RECOVERING` 冷却信息。
- `interacting` 是**边沿**语义。

### 4.4 `TimelineRecording`（定长缓冲 + 事件收集）
- `record(frame)` 强制校验 `frame.tick() == 已写入帧数`。
- `recordEvent(event)` 收集事件，**不在收集时排序**。
- 满 `durationTicks` 才能 `seal()`，封时按 `TimelineEvent.STABLE_ORDER` 排序事件；只一次；封后拒绝写入。
- `frameAt(tick)` / `frames()` / `events()` / `eventsAt(tick)`。

### 4.5 `TimelineEvent`（record，不可变）
`(long tick, String actorId, int sourceRound, String mechanismId, EventType eventType, Direction leaveDirection, String reason)`。

5 类事件（显式 `priority()`，**不依赖 `ordinal()`**）：

| priority | EventType | 残影能否触发 |
|----------|-----------|-------------|
| 10 | `DOCK_LEFT` | ✅ |
| 20 | `OCCUPANCY_RELEASED` | ✅ |
| 30 | `DOCK_ENTERED` | ✅ |
| 40 | `MECHANISM_STATE_CHANGED` | ✅ |
| 50 | `EXIT_REQUESTED` | ❌ 玩家专属 |

### 4.6 `EchoState`（单残影）
- `of(recording)` 只接受**已封装满长记录**。
- `frameAt(roundTick)` 按共享 roundTick 直接索引——**无独立时钟、不重算任何逻辑**。
- `eventsAt(tick)` / `allEvents()`：过滤掉 `EXIT_REQUESTED`（残影不能操作出口）。

### 4.7 `EchoLifetime`（寿命公式，README 原样）
- 输入 `(sourceRound, L, durationTicks, currentRound, roundTick)`，输出 `age / active / remainingRounds / lifeProgress / bodyAlpha`。
- 推荐 `of(sourceRound, L, TickContext)` 工厂：轮次/刻从共享时钟派生。
- `isLastEffectiveRound()` / `shouldDisappearAtRoundEnd()` 供 HUD 与消散判定。

### 4.8 `EchoQueue`（滑动窗口，容量 2）
- `addOnRoundEnd(echo, nextRound)`：加入本轮残影并按 `nextRound - s > L` 在边界淘汰。
- `activeEchoes(currentRound)`：按 sourceRound 升序（较旧在前）。
- `lifetimes(TickContext)`：每个活跃残影的只读寿命视图。

### 4.9 `RecordingSession`（轮末事务 + 事件转发）
- `beginRound()`：开新缓冲。
- `recordFrame(frame)`：仅 `PLAYING` 接受。
- **`recordEvent(event)`**：仅 `PLAYING` 接受，转发到当前缓冲。
- `completeNormalRound(Runnable restorer)`：封装→生成残影→入队淘汰→恢复机关→`RESETTING→READY`→开新缓冲。
- `failFinalRound()` / `completeGoal()` / `restartFromFirstRound(Runnable restorer)`。
- ⚠️ `Runnable` 占位待集成层注入 `AutoDockService.reset(reason, tick)`。

### 4.10 `ReplayPort`（W3）
- `currentPlayerFrame()`：读当前玩家帧，无缓冲时返回 `Optional.empty()`。
- `activeEchoFrames()`：按 sourceRound 升序返回 `List<EchoFrameView>`。

### 4.11 `EchoFrameView`（W3）
`(int sourceRound, PlayerFrame frame, int remainingRounds, double lifeProgress, double bodyAlpha)`。

### 4.12 `MvpRenderSnapshot`（W4）
`(GamePhase phase, long roundTick, int currentRound, int maxRounds, PlayerFrame currentPlayer, List<EchoFrameView> activeEchoes)`。  
不可变；列表为 `List.copyOf`；渲染零回写。

### 7.1 开发三 W2 硬阻塞详情

依据开发一 `MVP第一关-装配前置核查.md` §三：

```
[ASSEMBLY-PROBE] LevelGeometryImpl(Level01Footsteps.build()) -> FAILED:
IllegalArgumentException: 非法孤点: 节点 L01_node_left_end 没有任何相邻节点
```

- **原因**：`LevelGeometryImpl` 要求路径节点的每个合法出口在**恰好 1 tile**（`tileSize=48`）处存在相邻节点；而 `Level01Footsteps` 的路径节点相距 **3+ tiles**。
- **归属**：`level/**` 属**开发三**允许路径，开发一/二/集成不得修改。
- **佐证**：开发三自己的规格文档 §8 结尾写明"下一步 W2 负责修复第一关路径图并完成 `LevelGeometryImpl` 构造验收"。
- **旁证**：全仓（含测试）没有任何 `new LevelGeometryImpl(...)` 的调用/测试（除 AssemblyProbeTest）。

### 7.2 `tryLeave` 偏差

依据开发一文档 §5：

| 项 | 内容 |
|----|------|
| 现状 | `AutoDockOccupancyPort.tryLeave` 要求位置已在区域外，`DOCK_LEFT` 记在**出界刻** |
| README 要求 | "离开驻留型机关时，角色立即出发，对应占用同时释放" |
| 选项 A | 开发三放宽 `tryLeave`：离开刻按下合法出口即释放，`DOCK_LEFT` 记在离开刻 |
| 选项 B | 维持现状（出界刻），修订 README 措辞 |
| 开发二影响 | 回放时以**事件自带 tick** 为准；裁决前按选项 B 准备用例 |


## 8. 集成层装配方式（供接手人参考）

PM 已在 `app/` 完成集成装配（`Level01Assembly.java` 313 行 + `TimeTraceLabApplication.java` 115 行 + `InputAccumulator` + `PathGraphBridge`）。

### 每 tick 调用顺序

```java
// 1. 采集输入（开发一）
InputIntent input = inputAccumulator.sample(tick);

// 2. 开发一 C3：策略判定 + 产生事件
C3DockDecision decision = c3DockController.step(tick, input, playerPosition);

// 3. 开发二：转发事件到录制
for (TimelineEvent event : decision.events()) {
    session.recordEvent(event);
}

// 4. 开发二：记录玩家帧
session.recordFrame(playerFrame);

// 5. 按 decision 推进或冻结运动
if (!decision.isFreeze()) {
    // 按 decision.departureDirection() 推进
}

// 6. 开发二：渲染读取
// PM 已用 EchoQueue.activeEchoes(round) + EchoState.frameAt(tick) 等价替代 ReplayPort
// PM 已用 render/RenderViews 等价替代 MvpRenderSnapshot
```

### 轮末事务接线

```java
// 普通轮末
session.completeNormalRound(() -> 
    autoDockService.reset(AutoDockResetReason.ROUND_END, boundaryTick));

// 整局重开
session.restartFromFirstRound(() -> 
    autoDockService.reset(AutoDockResetReason.FULL_RESTART, boundaryTick));
```

**注意**：PM 在 `app/Level01Assembly` 中已用 `EchoQueue.activeEchoes(round)` + `EchoState.frameAt(tick)` 等价替代了 `ReplayPort`，用 `render/RenderViews` 等价替代了 `MvpRenderSnapshot`。**开发二的 `ReplayPort` / `MvpRenderSnapshot` 保留供后续 R6 使用。**

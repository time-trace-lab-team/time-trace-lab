# 游戏机关模块、事件通知体系、状态机系统交接文档

## 一、文档目的

本文档基于已完成的【第一关地图数据模块】代码，对**事件通知架构（最小观察者模式）**、**全部游戏机关组件状态机定义**、**模块职责边界**、**前后端衔接规则**、**待开发任务**进行标准化交接，为后续机关逻辑、游戏交互、关卡联动、时空共振系统开发提供统一规范与接口标准。

## 二、现有已完成模块（交接基准）

当前已完整实现**关卡数据层（Model 层）**，完全无业务逻辑、无渲染、无状态更新，为纯静态配置模块：

1. Vector2D：全局世界坐标体系
2. TileType：地形通行规则定义
3. PathNode：角色巡行路径节点数据
4. EntitySpawnInfo：所有机关的生成位置与初始参数配置
5. LevelData：关卡顶层数据容器（时长、轮次、残影寿命、地形、机关列表）
6. Level01Footsteps：第一关完整地图硬编码配置
7. JUnit5 全套数据校验测试类

现有模块**只负责 "描述关卡长什么样"**，**不包含任何交互、状态、触发、联动逻辑**。  
所有机关动态行为、状态切换、触发联动、时空规则全部交由 **mechanism 机关层 + 事件总线系统** 实现。

## 三、全局事件通知架构设计（最小观察者方案）

为避免复杂 EventBus 冗余依赖，本项目采用**极简原生观察者模式**作为全局消息中枢，满足所有机关联动、开关互锁、射线触发、共振传播需求。

### 架构特点

- 无第三方框架依赖，纯 JDK 实现，轻量、低耦合、适配 JavaFX 桌面游戏。
- 统一 **事件发布 - 订阅** 机制，所有机关、门、射线、共振节点**不直接互相持有对象**，完全通过事件通信。
- 支持：状态变更通知、开关触发、脉冲瞬时事件、共振扩散、射线命中、通关事件。

### 核心角色

1. **事件中心（EventDispatcher）**：全局单例，负责注册监听、移除监听、分发事件。
2. **观察者接口（GameObserver）**：所有可响应事件的机关、门、终端统一实现。
3. **事件实体（GameEvent）**：统一封装事件类型、触发者、参数、状态。

### 适用场景

- 压力板按压 / 松开
- 各类开关打开 / 关闭
- 时滞射线触发
- 共振节点激活、中继传导
- 代际感应板轮次感应
- 大门解锁、锁定
- 出口终端可通关事件

### 模块约束

- **数据层（level）禁止订阅 / 发布事件**
- **所有动态交互逻辑统一收敛到 mechanism 层**
- 所有跨机关联动禁止硬编码依赖，必须走事件总线

## 四、模块层级交接关系

**上层（已完成）**  
Level 数据模块：提供所有机关**生成位置、初始参数、关卡配置**

**中层（待开发核心）**  
Mechanism 机关层：
- 事件总线、观察者体系
- 所有机关状态机逻辑
- 机关联动、时序、共振、代际判定

**下层（后续对接）**  
Game 游戏循环层：
- 每帧 tick 更新机关状态
- 接收状态变化、驱动动画与碰撞

**表现层（JavaFX）**  
View 渲染层：
- 只根据机关**最终状态**做绘制
- 不参与任何逻辑判断

## 五、开发强制规范（交接约束）

1. 所有机关**状态必须枚举化**，禁止零散布尔变量控制逻辑
2. 所有跨机关联动**必须通过事件总线**，禁止直接 new 对象、禁止跨类调用
3. 数据层与逻辑层完全解耦，LevelData 只做配置，不做更新
4. 所有机关重置、轮回复位逻辑统一实现 reset() 接口
5. 所有状态变更必须可被监听、可被日志打印、可被单元测试

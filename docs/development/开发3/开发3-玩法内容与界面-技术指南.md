## 0. 使用方法与强制边界

开发 3 的范围最宽，因此最容易让一次任务跨越机关、关卡、页面和存档。每次 AI 编码仍只能实现第 5 节的一个模块；同一天可以有多张任务卡，但每张卡必须独立审查、验证和提交。

### 0.1 每张任务的闭环

1. 选择一个 P 模块，并进一步写出一个可在半天内验收的单一目标。
2. 阅读 README 对应规则、本指南第 1～3 节、该模块和第 6 节。
3. 写明允许路径、禁止路径、已有接口版本、固定关卡数据和可观察效果。
4. AI 只能改任务卡列出的文件；不得顺手实现移动、回放、Canvas 或场景骨架。
5. 成员 D 检查每个状态、事件、数据字段、资源许可证和失败回退。
6. 先跑纯逻辑/数据测试，再由开发 1 的画面和开发 2 的时钟进行最小集成验收。
7. 跨模块时停止编码，只提交契约需求；由项目经理拆卡并确定提供方。

README 冻结规则优先于接口决定和本指南。AI 提出的额外机关、关卡、评分、生命、死亡、随机射线或复杂动画必须直接删除，而不是列为“可选扩展”。

### 2.4 事件规则

- 机关通过事件连接，不能让门直接持有某块板的具体对象引用。
- 事件在 tick 内先收集、后按稳定规则统一处理；同一输入得到同一顺序。
- actor 类型必须区分当前玩家与残影；残影还必须带 `sourceRound`。
- 事件只表达边沿，例如进入/离开/激活/释放；持续占用是机关状态，不每 tick 重发进入。
- 未知 ID、重复 ID、悬空引用和非法状态转移在关卡加载时报告完整上下文，禁止静默忽略导致不可解关卡。

## 3. 技术原理

### 3.1 事件驱动的机关，而非相互硬引用

最小数据流：

```text
玩家/残影产生规范事件
  -> 本 tick 事件批次（稳定排序）
  -> 机关状态机消费允许的事件
  -> 更新门/共振网络/中继/核心状态
  -> 产生只读状态与反馈事件
  -> 开发 2 记录/快照，开发 1 绘制
```

门只关心“条件 ID 是否满足”，不调用驻留板实例。核心只读取两个中继的供能状态和当前玩家交互。这样可单测状态机，也避免循环依赖。

### 3.2 autoDock 的机关侧语义

驻留板和共振中继共用 `autoDock=true`：

```text
UNOCCUPIED --允许 actor 进入--> OCCUPIED/ACTIVE
OCCUPIED --该 actor 按记录或新方向离开--> UNOCCUPIED/RELEASED
```

- 进入时开发 1 负责把当前玩家置为 `DOCKED`、清队列；机关只维护占用者与激活状态。
- 残影按开发 2 记录的进入/离开事件复现；不重新读取键盘。
- actor 被淘汰、整局重开或场景退出时必须释放占用。
- 第四、五关共振前不得配置任何 autoDock；共振后的 I/II 中继可以自动停驻。
- 两个 actor 同 tick 进入、错误离开者、重复进入都需要稳定规则和测试。

### 3.3 唯一的射线规则

所有射线只有一套 `OFF -> WARNING -> ACTIVE` 周期，由共享 `roundTick` 和进入关卡时冻结的参数计算；暂停、教程与掉帧不能独立推进。

- 只允许两个墙面发射器之间的水平/垂直有限线段，内部墙会遮断；不做斜线、旋转、追踪或随机射线。
- 推荐预警 1.0～1.4 秒、激活 0.8～1.2 秒、判定宽度 `0.18～0.25 × tileSize`。
- 当前玩家非 `PHASED` 命中：`slowMultiplier=0.50`、`slowDurationTicks=120`；同一射线激活周期只结算一次，不叠加、不刷新。
- 命中不扣生命、不死亡、不进 `FAILED`、不中断录制。
- 残影完全不参与射线结算，只显示记录结果。
- 第二关与第五关的颜色、线型、Δt 图标、声音、预警和命中规则完全相同。

相位公平性必须满足：

```text
warningTicks >= reactionBudgetTicks + inputBufferTicks
phaseDurationTicks >= beamCrossingTicks + timingMarginTicks
```

其中反应预算至少 24～30 tick，输入缓冲 6～10 tick，成功余量至少 12 tick；相邻需要分别相位的射线间隔要容纳 45 tick 恢复期。

第二关到达刻必须用固定步长模拟验证：

```text
noLagArrivalTick + interactionBufferTicks <= durationTicks - successMarginTicks
laggedArrivalTick > durationTicks
```

`successMarginTicks` 建议 24～36 tick。第五关还必须证明：

```text
delayTicks ≈ slowDurationTicks × (1 - slowMultiplier)
abs(arrivalTickA - arrivalTickB) > resonanceWindowTicks
abs((arrivalTickA + delayTicks) - arrivalTickB) <= resonanceWindowTicks
```

估算约 60 tick 延迟只能用作起点，最终采用模拟到达刻。

### 3.4 固定区域共振与双中继因果链

共振区是 JSON 中明确的圆或圆角矩形，不是轨迹相交。actor 的 `resonanceAura` 与区域相交并发生 `outside -> inside` 才产生一次事件；持续停留不刷新，同 tick 事件先按 `sourceRound` 排序。

```text
DORMANT
  --第一个残影进入--> ARMED(30～45 tick)
ARMED
  --不同 sourceRound 残影在窗口内进入--> LATCHED
  --超时--> DORMANT
LATCHED
  --保持到本轮结束--> 下一轮 DORMANT
```

- 当前玩家只能产生预览，不能改变实际状态机；第二轮“玩家 + E1”绝不激活。
- 同一来源不能完成共振；最早第三轮由 E1+E2 激活。
- LATCHED 只接通能量网络，不打开出口。
- 两条参与记录在共振后必须各自到 I/II 中继并停驻；当前玩家再走独立路线操作核心，出口才可用。
- 共振前无 autoDock，不能用停车取代路线/时滞规划。
- 共振区域判定大小与 2～4 px 轨迹绘制宽度完全分离。

### 3.5 UI 是状态投影与命令入口

合法页面/阶段只有 README 列出的 `BOOT/MENU/LEVEL_SELECT/TUTORIAL/READY/PLAYING/PAUSED/RESETTING/FAILED/RESULT`。UI：

- 读取只读快照，提交明确命令；不直接 set 时间系统字段；
- HUD 只显示一个共享秒级读秒，可显示“当前轮/最大轮”、sourceRound、剩余存活轮数和非数字相位恢复环；
- `FAILED` 只表示最终轮到时未通关；没有死亡页面；
- 暂停/失败的“从第一轮重开”必须调用开发 2 的完整事务端口；
- H 提示和教程镜头在 TUTORIAL/READY 期间不推进 tick、不记录、不生成残影；
- 所有状态不能只靠颜色，还要有形状、编号、线型、亮度或声音。

### 3.6 数据驱动五关，而不是五套硬编码

关卡 schema 至少需要以下概念，确切字段名待团队确认：

```text
schemaVersion, levelId, displayName,
tileSize, durationTicks, maxRounds, echoLifetimeRounds,
spawn, pathNodes, pathEdges, walls,
mechanisms, links, tutorialSteps, visualTheme
```

加载顺序：解析 → schema 版本 → 必填字段/范围 → ID 唯一 → 引用存在 → 路径/几何合法 → 机制组合合法 → 固定参数冻结 → 工厂创建 → 初始快照。任何一步失败都不得进入半可玩的关卡。

只允许五关：

| 关 | 冻结重点 | 初始参数 | 必须证明 |
| --- | --- | --- | --- |
| 1 留下的脚步 | 恒速、autoDock、单残影双板门 | 16 s，L=1，max=3 | 第一轮停左板，第二轮当前玩家停右板并操作出口 |
| 2 低姿穿行 | 相位教学、统一射线 | 16 s，L=1，max=3 | 正确相位可到达，命中通常超时但不死亡；正式解最多两次 Space |
| 3 即将褪去 | E1/E2 寿命和补救 | 18 s，L=2，max=4 | 第 3 轮 E1 最后有效且先消散，影响主解/补救 |
| 4 双迹同频 | 固定共振、双中继 | 20 s，L=2，max=4 | 第二轮仅预览；第三轮 E1+E2 锁存后继续到 I/II |
| 5 回声交点 | 故意接受同一时滞 | 22 s，L=2，max=5 | 避开时不能共振，接受减速后才进入窗口；E1 消散构成压力 |

正式 tick 值须由 60 Hz 固定步长模拟得出。关卡 4/5 的共振建议发生在路线 35%～55%，中继位于 60%～80%，当前玩家核心操作位于 80%～95%。

### 3.7 存档：小数据、原子替换、安全回退

只保存设置、已通关关卡和教程查看状态，不保存分数、收集品、当前轮或残影。

- 数据包含 `schemaVersion`，字段缺失使用明确安全默认值，未知未来字段可忽略但要保留兼容策略。
- 写入同目录临时文件，确保完整写入后以原子移动替换；不直接覆盖原文件中途失败。
- 路径使用 `java.nio.file` 与系统用户数据目录策略，具体目录由项目经理批准；不能提交个人绝对路径。
- 损坏文件保留诊断上下文并回退默认设置/未解锁进度，不能让游戏无法启动。
- 测试使用临时目录，不碰真实用户文件。

### 3.8 视觉与音频是规则反馈

- 视觉基于 README 的原创暗调几何色板、连续地面、内外墙、局部菱形节点和 4～8 px 偏移；不画全屏格线。
- 共振用双分段环、I/II、预览虚环、ARMED 缩短弧、LATCHED 闭环/波纹与能量流；不增加数字倒计时。
- 射线、相位和残影同时使用颜色以外的线型、轮廓、图标和声音。
- 最小音效仅含射线预警/命中、共振单音/和弦、轮次切换和通关。
- 音频缺失时记录错误并继续使用视觉反馈；不能因单个音效阻断关卡。
- 每个外部资源必须进入许可证清单；不能复制商业游戏角色、关卡、构图或素材。

## 5. 单模块实施卡

### 5.1 P0：工程、schema 与状态稿门禁

**目标**：在写机关前冻结数据语言、五关纸面时间表和视觉状态含义。

**技术原理**：先以状态表和固定 tick 数据证明可解，再让工厂从数据创建对象；状态稿定义反馈，不定义碰撞。

**顺序**：核对 JSON/JUnit/Maven 差距 → 五关逐轮时间表 → schema 字段/校验 → 机关状态表 → 页面流 → 三方契约评审 → 只建立获批最小数据类型。

**边界**：引入 JSON 依赖未审批、字段单位混用秒/tick、显示名当 ID、先画漂亮地图后发现不可解。

**验收**：五关各有“轮次 × tick × actor × 机关”表；非法样例有明确错误；没有第六关或新机关。

**完成定义**：POM、业务代码和其他板块未被顺手修改。

### 5.2 P1：事件总线、驻留板、门与终端

**目标**：用纯状态机形成第一关所需的最小因果链。

**依赖**：开发 1 的进入/离开事件，开发 2 的 actor/sourceRound 与快照端口。

**顺序**：冻结事件类型 → 驻留占用 → 释放 → 条件聚合 → 门可通行状态 → 当前玩家终端权限 → 快照/恢复 → 非法事件诊断。

**边界**：重复进入、错误 actor 离开、同 tick 两 actor、残影淘汰、重开、门关闭时 actor 位于门区、残影误操作出口。

**自动测试**：autoDock 进入/离开矩阵；门监听条件；残影可占板但不能操作终端；轮次恢复和会话重开无残留。

**手工验收**：第一关完整“旧残影占一板 + 当前玩家占另一板 + 当前玩家操作出口”。

**完成定义**：机关间无具体对象硬引用，事件顺序稳定且状态可快照。

### 5.3 P2：统一射线与第 1/2 关数据

**目标**：完成前两关，尤其证明第二关的相位是可读、宽容且非死亡式。

**依赖**：开发 1 的相位/碰撞候选，开发 2 的共享 tick/记录。

**顺序**：射线周期纯函数 → 线段与遮挡数据 → 每周期 actor 去重 → 时滞命令 → 统一反馈状态 → 固定步长到达刻模拟 → 教学单束 → 相邻双束门 → 试玩调参。

**边界**：暂停、轮次初相位、同周期连续相交、PHASED、已处于 SLOWED、残影、内部墙截断、命中后仍录制。

**自动测试**：OFF/WARNING/ACTIVE 边界；同周期只一次；不叠加/刷新；残影不结算；命中不 FAILED；两条公平性公式和到达刻条件。

**手工验收**：五人各 5 次、理解后无时滞率至少 80%；正式解最多两次 Space；命中只导致通常赶不上本轮。

**完成定义**：第二/五关共享同一射线定义，无绕路替代、跳跃、护盾、死亡或第二套模式。

### 5.4 P3：第 3 关与寿命教学

**目标**：让 E1 最后有效轮和先行消散真正影响解法，而非只换透明度。

**依赖**：开发 2 提供 sourceRound、remainingRounds/lifeProgress 和轮末淘汰；开发 1 绘制虚线/外环。

**顺序**：远/近板路线测量 → 第 1/2 轮记录目标 → 第 3 轮主解 → E1 状态稿/提示 → 第 4 轮补救路线 → 淘汰占用释放 → 未参与设计者试玩。

**边界**：E1 消散后门仍开、玩家看不出哪条先消失、错误路线无法补救、maxRounds=4 被动态放宽。

**自动测试**：第 3 轮 E1+E2；E1 最后轮；边界先释放 E1 占用；E2 保留。

**手工验收**：测试者能说明第三轮主解和错过后的补救选择，不依赖颜色识别。

**完成定义**：第三关只增加数量/寿命，不偷偷加入共振或新机关。

### 5.5 P4：共振状态机与第 4/5 关

**目标**：实现唯一高阶机制，并让第五关必须把时滞写入 E1。

**依赖**：开发 2 的两个残影/sourceRound/共享 tick，开发 1 的 aura 相交候选与只读绘制。

**顺序**：固定区域边沿 → 同 tick 稳定事件批次 → DORMANT/ARMED/超时/LATCHED → 玩家预览分支 → I/II 中继 → 核心 → 出口 → 第 4 关宽容表 → 第 5 关到达刻对照 → 生命周期压力。

**边界**：同来源重复、当前玩家误激活、持续停留刷新、刚超时同 tick 进入、锁存后离开、轮末复位、中继顺序、E1 淘汰释放。

**自动测试**：第二轮仅预览；第三轮不同来源锁存；同来源无效；窗口边界；锁存至轮末；共振不能直接开门；双中继+当前玩家核心才结算；第五关避开/接受的固定 tick 对照。

**手工验收**：玩家能从环、I/II、线路、轨迹和声音判断过早/过晚及缺哪路能量；第五关 E1 消散前完成因果链。

**完成定义**：共振不是任意轨迹交点、普通双人按钮或终点；准备记录均含“共振区 + 中继”两个锚点。

### 5.6 P5：菜单、HUD、暂停、失败/结算与教程

**目标**：形成完整页面流，并保持 UI 对时间/玩法只读。

**依赖**：项目经理场景端口、开发 2 状态/命令端口、开发 1 Canvas 容器。

**顺序**：页面流图 → 公共 ViewModel/快照 → 主菜单/选关 → TUTORIAL/READY → HUD → 暂停 → FAILED/RESULT → H 提示/重播 → CSS 统一 → 场景清理。

**边界**：快速重复点击、暂停后重开、最后一轮失败、教程跳过/重播、场景返回后 listener 泄漏、缩放与键盘焦点。

**自动测试**：纯 presenter/ViewModel 状态；命令映射；HUD 只有一个秒级倒计时；射线命中不出现失败页面。

**手工验收**：从主菜单到五关、结算、失败、重开和返回选关完整无阻塞；教程期间 tick 冻结。

**完成定义**：UI 不直接持有可变 replay/mechanism 内部对象，不存在评分/收集页面。

### 5.7 P6：本地进度与最小音效

**目标**：可靠保存三类小数据，并接入不阻塞玩法的必要声音。

**顺序**：冻结 schemaVersion → 默认值 → 临时目录测试 → 读/写/原子替换 → 损坏回退 → 通关解锁流程 → 音效事件映射 → 缺资源回退 → 许可证清单。

**边界**：目录不可写、写一半、空文件、未知版本、字段缺失、音频设备不可用、反复进关导致播放器/监听器累积。

**自动测试**：临时目录 round-trip；损坏/缺字段/未知字段；写失败保留旧文件；只解锁 README 五关。

**手工验收**：重启后设置/进度/教程状态正确；静音与音量正常；无音频仍可玩。

**完成定义**：不保存本局残影或成绩；资源来源完整，无个人绝对路径。

### 5.8 P7：五关调参、可读性与发布收尾

**目标**：第 6 天功能冻结后使恰好五关可稳定通关并可演示。

**顺序**：固定模拟数据 → 五关从菜单全通 → 未参与设计者试玩 → 阻塞/高缺陷 → 暗调/非颜色检查 → 资源与清理 → 演示路线彩排。

**边界**：用扩大范围解决难度、为赶工删掉必要机制、第五关存在普通等待替代、关卡列表/存档出现第六关、视觉修补碰撞。

**验收**：每关 2～5 分钟；高级关理解后依赖路线选择而非单帧操作；所有提示不改变时钟。

**完成定义**：第 7 天以后只修阻塞/高优先级；第 8 天交付五关数据、页面、存档、音效、许可和演示证据。

### 6.4 人工审查清单

## 4. 修复的三个缺陷（重要，别改回去）

### D-01【高】持续掉帧后产生无法清偿的债务，恢复帧率后 5 倍速快进

**现象**：每帧 `delta` 只执行最多 5 步，但剩余余额留在累加器里滚到下一帧。实测 60 帧 × 200ms 掉帧后 `alpha = 420`，恢复帧率后仍以 5 倍速跑约 95 帧才还清。

**危害**：快进期间一渲染帧推进 5 个逻辑刻，`PHASED` 的 30 tick 相位窗口在画面上只剩 6 帧，直接击穿 README 的 24–30 tick 反应预算。

**修复**：补算达上限后豁免债务。

```java
if (steps == MAX_STEPS_PER_FRAME && accumulator >= STEP_SECONDS) {
    accumulator = 0.0;   // 宁可丢时间，也不欠债
}
```

**注意**：掉帧期间 `totalTicks` 少于理论值是**正确行为**，指南 3.1 要的就是「让游戏视觉时间变慢」。修复消除的是「事后快进还债」，不是「掉帧时变慢」。

### D-02【低】时间源回退产生负累加器

**现象**：`nanoTime` 回退时 `delta` 为负，实测 `alpha = -60`，渲染插值会让实体向后跳一帧。

**修复**：

```java
if (delta <= 0.0) {
    return 0;
}
```

### D-03【中】阶段判断用白名单，新增阶段会静默推进逻辑刻

**现象**：原写法只拦截 `BOOT/READY/PAUSED`，其余默认推进。PM 一旦加 `TUTORIAL/RESETTING/RESULT/FAILED`，这四个会全部被当成 `PLAYING` 推进 `roundTick`，违反《开发 2 指南》3.1，且**不报任何错**。

**修复**：改成黑名单，安全默认。

```java
if (phase != GamePhase.PLAYING) {
    lastNanoTime = nanoTime;
    return 0;
}
```

配套测试 `onlyPlayingPhase_advancesLogicTicks` 遍历 `GamePhase.values()`，PM 每加一个阶段都会被自动检查。

### 4.1 为什么要记这三个

它们**都不是靠正常运行发现的**，是人工时间源探针跑出来的。现有测试一开始全绿却完全没覆盖到。所以后续每个模块请把「持续异常输入」纳入必测项，不要只测正常路径 + 单个极值。

### 7.2 坑一：带斜杠的分支引用会静默丢失

这台机器上 `refs/heads/feature/*`、`refs/remotes/origin/feature/*` 会在 commit/push 后**丢失**。
症状：`git commit` 明明打印成功，随后 `git rev-parse HEAD` 却报 `does not have any commits yet`，`git branch -v` 里分支不见了。

**数据不会丢**，丢的只是指针，reflog 里有完整历史。恢复：

```bash
# 本地分支
FULL=$(tail -1 .git/logs/refs/heads/feature/<分支名> | awk '{print $2}')
mkdir -p .git/refs/heads/feature
printf '%s\n' "$FULL" > .git/refs/heads/feature/<分支名>

# 远程跟踪分支同理，路径换成 .git/refs/remotes/origin/feature/<分支名>
```

`git update-ref` 在这台机器上**无效**（返回 0 但不产生文件），别浪费时间。

**每次 commit / push 后都要用 `git rev-parse HEAD` 复核。**

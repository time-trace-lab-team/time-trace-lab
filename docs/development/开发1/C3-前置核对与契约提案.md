## 2. 契约提案 A：`InputIntent`（逻辑输入，待 PM 裁决归属）

**定位**：JavaFX `KeyEvent` 只在边界层转成不可变逻辑输入；逻辑层不保存 `KeyEvent`，也不读 `Scene`/`Node`。

**字段提案**（不可变 record，候选名待确认）：

```java
public record InputIntent(
        long tick,                         // 该输入归属的逻辑刻（tick 边界，与 PlayerKinematics.tick 对齐）
        Set<LogicalKey> pressedThisTick,   // 本刻新按下（边沿，用于 Space/E 与方向替换）
        Set<LogicalKey> releasedThisTick,  // 本刻释放（用于失焦/漏 release 的对账）
        Set<LogicalKey> held,              // 本刻结束时仍按住（用于 autoDock 防误离开的“旧键快照”）
        List<Direction> directionEdges     // 本刻方向类新按下，按发生顺序；末位即单槽队列应保留者
) {}
```

**`LogicalKey` 提案**（逻辑键，不含物理键码）：

```java
public enum LogicalKey { DIR_UP, DIR_DOWN, DIR_LEFT, DIR_RIGHT, INTERACT /*E*/, PHASE /*Space*/ }
```

**关键语义（请 PM 确认）**：

1. **同义键合并**：`W/A/S/D` 与方向键映射到同一 `LogicalKey`，物理键差异不进入逻辑层。
2. **边沿 vs 按住**：只有 `pressedThisTick` 产生动作（方向排队、Space、E）；`held` 只用于 autoDock 进入瞬间的“旧键快照”，持续按住不得触发第二次。
3. **同刻多方向**：`directionEdges` 有序，单槽队列取**末位**（最后一次新按下胜出）；需 PM 确认“末位胜出”而非“首次胜出”。
4. **tick 归属**：一批按键边沿在**本刻逻辑更新之前**采集并入 `InputIntent(tick)`；逻辑层不得跨刻补算。
5. **纯逻辑可测**：`InputIntent` 与 `LogicalKey` 均为纯 Java，可在无 JavaFX Toolkit 的 JUnit 中构造。

**归属与适配位置（PM 裁决项，见 §5-A）**：`core/` 必须保持 JavaFX 无关，因此 `KeyEvent → InputIntent` 适配器不能放进 `core/`。

## 3. 契约提案 B：`DockEvent`（autoDock 边沿事件，交给开发二的 `TimelineEvent`）

**定位**：C3 在解析 autoDock 的同一刻发布**边沿**事件；持续 `DOCKED` 不逐刻重发“进入”。

**字段提案**：

```java
public record DockEvent(
        long tick,              // 事件发生的逻辑刻
        String actorId,         // 稳定 actor ID：当前玩家固定值；残影用 echo_<sourceRound>
        int sourceRound,        // 当前玩家 = 0；残影 = 来源轮次
        String mechanismId,     // 稳定 autoDock 机关 ID（开发三冻结规则）
        DockEventType type,     // DOCK_ENTERED / DOCK_LEFT / OCCUPANCY_RELEASED
        Direction exitDirection,// 仅 DOCK_LEFT 有意义，其余为 null
        DockExitReason reason   // 仅 DOCK_LEFT 有意义：NEW_DIRECTION / ECHO_EXPIRED / SESSION_RESTART
) {}
```

**事件类型（至少，与卡 #1 对齐）**：

| 类型 | 触发时机 | 载荷 |
| --- | --- | --- |
| `DOCK_ENTERED` | 进入 `autoDock=true` 区域瞬间（同刻清空旧方向队列） | 无 |
| `DOCK_LEFT` | 新按下合法方向边沿后以 `baseSpeed` 离开 | `exitDirection` + `reason` |
| `OCCUPANCY_RELEASED` | 残影淘汰 / 整局重开 / 退出关卡导致占用释放 | `reason` |

**稳定排序键提案**（同 tick 确定性，不依赖集合迭代顺序）：

```text
sortKey = (tick, categoryPriority, mechanismId, actorId, sourceRound)
categoryPriority: DOCK_ENTERED(0) < DOCK_LEFT(1) < OCCUPANCY_RELEASED(2)
```

`mechanismId` / `actorId` 均要求**稳定字符串**（禁止对象地址、集合下标、本地化显示名）。

**采集时点（与开发一指南 §2.4 的单刻顺序一致）**：

```text
采集本 tick 输入边沿
  -> 更新方向队列 / 相位状态
  -> 沿路径推进并在节点提交转向
  -> 解析墙、门、autoDock、终端（产生 DockEvent 候选）
  -> 统一发布本 tick 事件（按上面的排序键排序）
  -> 开发二在 tick 末记录规范 PlayerKinematics      <- 事件先于帧记录
  -> 生成只读 RenderSnapshot -> Canvas 绘制
```

> 卡 #2 验收要求“与开发一确认事件在 `PlayerKinematics` 之前采集、在 `advance()` 前记录”——上表即该约定的具体化，请 PM 与开发二确认措辞。

## 4. 与现有 C2 代码的衔接点（不动 C2，仅说明扩展位置）

| 现有 | C3 扩展点 |
| --- | --- |
| `PatrolController.advance(tick, passability)` 当前**硬编码返回 `MovementState.CRUISING`** | C3 需按 tick 结果返回 `DOCKED`（autoDock 驻留）或沿用 `SLOWED`（射线命中，属开发三规则） |

| `LevelGeometry` 无 autoDock 查询 | 需开发三补只读查询（区域形状/边界、停驻中心、合法出口、占用释放） |
| `PlayerKinematics` 无“正在交互的目标” | E 交互的目标 ID 建议经事件而非塞进帧字段（待 PM 确认） |

1. 选定一个 R 模块并建立一张任务卡。

### 2.4 不可变性和时间约定

- 逻辑频率建议固定 60 Hz，所有持续时间先转为整数 tick 并在关卡加载时冻结。
- `roundTick` 的有效帧索引为 `0 .. durationTicks - 1`；一条成功封装记录正好有 `durationTicks` 帧。
- 每个 `PlayerFrame.tick` 必须等于其列表索引；不得以浮点秒数查帧。
- 记录对象封装后不可变；残影不能持有仍在写入的缓冲列表。
- ID 使用关卡内稳定字符串或经批准的稳定值，禁止把对象地址、数组位置或本地化显示名当 ID。
- 同 tick 事件先批量收集，再按批准的类别优先级和稳定 ID 排序。
- 时间系统不使用随机数；如表现层使用粒子随机种子，也不能进入玩法与记录结果。

## 3. 技术原理与不变量

### 3.1 单一共享时钟

开发 1 的固定步长驱动每次请求“推进一个逻辑刻”，但 `roundTick` 的权威状态只有一份。所有当前玩家、残影和机关都读取同一个 tick；残影不累加 elapsed time，也不显示自己的秒级倒计时。

阶段约束：

- `TUTORIAL`、`READY`、`PAUSED`：不推进 `roundTick`、不写帧、不消费轮内倒计时；
- `PLAYING`：从 `roundTick=0` 开始，每完成一次规范逻辑更新写一帧；
- `RESETTING`：冻结玩法更新，执行原子轮次切换和短视觉过渡；
- `RESULT`：目标达成后立即结束，本轮不完整缓冲丢弃；
- `FAILED`：只在第 `maxRounds` 轮最后一个 tick 未通关时进入。

射线命中、暂停、退出和从第一轮重开都不能被解释成“生成残影的提前结束”。

### 3.2 位置快照 + 离散事件

只重放键盘输入会受碰撞、掉帧和未来代码变化影响。本项目每 tick 保存规范玩家状态，同时保存需要解释因果的离散事件。

连续帧至少表达：

```text
tick, x, y, direction, interacting,
movementState(CRUISING/SLOWED/DOCKED),
phaseState, animationState
```

事件只在状态边沿写入，例如：排队转向提交、终端交互、进入 autoDock、从 autoDock 离开、占用释放、共振/中继触发。持续 `DOCKED` 不应每 tick 重复发“进入”事件，但静止位置仍逐 tick 写帧。

### 3.3 残影是播放结果，不是第二个玩家

残影在 tick `t` 直接读取其记录的第 `t` 帧：

- 不重新执行输入、路径选择、碰撞、射线或 autoDock 逻辑；
- 不被射线二次减速；
- 不阻挡任何 actor；
- 只能通过记录事件触发 README 允许的残影机关；
- 不能操作只允许当前玩家使用的核心或出口；
- 时间线长度不合法时应在加载/构造边界明确失败，不能用最后一帧补齐。

### 3.4 普通轮次切换事务

只有非最终轮的统一读秒归零才执行：

```text
冻结 durationTicks - 1 的末刻结果
-> 校验并封装恰好 durationTicks 帧
-> 生成 sourceRound = currentRound 的新残影记录
-> 更新容量和整轮寿命窗口
-> 恢复轮内 RoundSnapshot
-> 保留 SessionState 中的记录与轮次参数
-> currentRound += 1，roundTick = 0
-> 进入 READY
-> PLAYING 时当前玩家与所有存活残影同步启动
```

这是一个事务。任一步失败不得留下“已加残影但机关未重置”等半完成状态；错误应携带关卡 ID、轮次和 tick 返回集成层。

### 3.5 通关、失败、退出和重开是四种不同边界

| 边界 | 当前缓冲 | 是否生成残影 | 清理范围 | 目标阶段 |
| --- | --- | --- | --- | --- |
| 非最终轮到时 | 必须满长并封装 | 是 | 恢复轮内状态 | `READY`（下一轮） |
| 目标达成 | 未满则丢弃 | 否 | 由场景流程清理 | `RESULT` |
| 最终轮到时未通关 | 丢弃/不封装新残影 | 否 | 冻结失败视图需要的数据 | `FAILED` |
| 暂停后从第一轮重开 | 丢弃 | 否 | 清空整个会话并恢复初始快照 | `READY`（第 1 轮） |
| 退出关卡 | 丢弃 | 否 | 清空整个会话 | 菜单/选关 |

项目没有生命值、死亡或射线即时失败。代码评审中出现 `onPlayerDeath` 或射线直接转 `FAILED` 应立即退回。

### 3.6 双残影滑动窗口和寿命公式

必须先通过单残影门禁，才把容器扩展为最多两个残影。令来源轮次为 `s`、当前轮次为 `r`、整轮寿命为 `L`、轮长为 `D=durationTicks`：

```text
age = r - s
active = 1 <= age <= L
remainingRounds = L - age + 1
lifeProgress = clamp(((age - 1) * D + roundTick) / (L * D), 0, 1)
bodyAlpha = 0.82 - 0.32 * lifeProgress
```

关键例子（`L=2`）：

| 当前轮 | 活跃残影 | E1 状态 | 轮末变化 |
| --- | --- | --- | --- |
| 1 | 无 | 未生成 | 生成 E1 |
| 2 | E1 | `age=1`，剩余 2 轮 | 生成 E2 |
| 3 | E1 + E2 | E1 `age=2`，最后有效轮 | 生成 E3 后淘汰 E1 |
| 4 | E2 + E3 | E2 最后有效轮 | 生成 E4 后淘汰 E2 |

淘汰只发生在轮次边界；不得因 alpha 变低在轮中移除。第三、五关第 3 轮结束时 E1 必须先于 E2 消散。`lifeProgress` 只供表现，不是新计时器。

### 3.7 三类状态所有权

| 状态类别 | 示例 | 普通轮次切换 | 从第一轮重开/退出 |
| --- | --- | --- | --- |
| 轮内状态 | 玩家、队列、相位、门、驻留、射线周期、共振、中继、核心 | 恢复初始轮内快照 | 清空并恢复 |
| 关卡会话 | 冻结参数、当前轮、残影、来源、剩余轮、提示 | 保留并推进 | 清空 |
| 存档状态 | 设置、已通关关卡、教程看过 | 不变 | 不因重开清空 |

`RenderSnapshot` 是上述权威状态的不可变投影，不是第四类可写状态。场景退出后不得由 Canvas、listener 或缓存继续持有旧会话。

## 5. 单模块实施卡

### 5.1 R0：工程与契约门禁

**目标**：在无业务实现前冻结可测试的最小时间语言。

**技术原理**：确定性来自单位、更新顺序、不可变边界和状态所有权，而不是类数量。

**实施顺序**：核对构建环境 → 画状态与数据流 → 定义 tick/帧语义 → 列候选契约 → 用表格演算一轮 → 三方评审 → 只建立获批的最小类型。

**风险**：类名先行但语义未定、开发 1/2 各自维护 tick、帧记录时点不一致、把 UI 秒数作为权威时间。

**验收**：给定 5 tick 的纸面样例，全员得到相同帧列表、事件顺序和边界结果。

**完成定义**：未修改 `pom.xml` 或其他板块；未批量创建未来类；契约带所有者与版本。

### 5.2 R1：共享时钟与游戏阶段

**目标**：提供唯一的逻辑 tick 与合法阶段转移，不实现玩家或 UI。

**依赖**：开发 1 每固定步请求一次更新；项目经理提供阶段切换端口。

**实施顺序**：冻结参数 → READY 初值 → PLAYING tick 推进 → 暂停冻结 → 轮末信号 → 只读查询 → 非法转移报错。

**边界**：`durationTicks=1`、暂停在 tick 0/末 tick、READY 重复进入、一次请求越过轮末、参数中途修改。

**自动测试**：TUTORIAL/READY/PAUSED 零推进；PLAYING 序列严格 0..D-1；没有 D 索引帧；参数对象不可变；非法状态转移明确失败。

**完成定义**：所有 actor 共享同一上下文；不存在残影计时器或第二倒计时。

### 5.3 R2：当前轮定长记录

**目标**：只在 PLAYING 为当前玩家记录恰好 D 帧和稳定排序的边沿事件。

**依赖**：开发 1 提供 tick 末 `PlayerKinematics`；开发 3 提供经批准的事件类型。

**实施顺序**：空缓冲 → 校验期望 tick → 复制不可变帧 → 收集并排序事件 → 满 D 后一次封装 → 冻结集合 → 拒绝后续写入。

**边界**：重复 tick、缺 tick、乱序事件、DOCKED 长静止段、离开后继续运动、暂停、相位和时滞、通关时未满。

**自动测试**：帧索引等于 tick；D-1 帧不能封装；D 帧只能封装一次；DOCKED 仍逐 tick 写帧；不完整缓冲丢弃；射线命中不截断。

**完成定义**：记录不持有可变玩家对象；错误含关卡/轮次/期望与实际 tick。

### 5.4 R3：单残影、普通轮次边界和失败/重开

**目标**：先完整证明一条时间线在下一轮从 tick 0 确定性播放。

**依赖**：轮内快照恢复端口、开发 3 机关事件消费端口、项目经理状态切换。

**实施顺序**：播放不可变帧 → 过滤残影允许事件 → 实现普通轮末事务 → 恢复快照 → 下一轮 READY → 最终轮 FAILED 分支 → 通关/退出/整局重开丢弃分支。

**边界**：播放记录长度错误、最后一 tick 机关事件、重置中异常、暂停后重开、当前玩家与残影同 tick 事件、最终轮不能生成无用残影。

**自动测试**：原记录与残影逐 tick 位置/状态相同；残影不重算射线；普通轮生成一条；RESULT/FAILED/重开/退出均不生成；完整重开回到第 1 轮 READY 且清理全部会话状态。

**手工验收**：第一关复现进入 autoDock、静止、按记录 tick 离开，并与当前玩家开门。

**完成定义**：单残影确定性门禁通过前没有双残影或共振实现。

### 5.5 R4：双残影、整轮寿命和暂停

**目标**：实现容量 2 的代际窗口和 README 原样寿命公式。

**依赖**：关卡进入时冻结 L；开发 3 第一二关用 L=1，第三至五关用 L=2。

**实施顺序**：单记录集合泛化 → 每轮开始按公式筛活跃 → 稳定按 sourceRound 排序 → 计算只读寿命视图 → 轮末加入新记录 → 淘汰超龄 → RESETTING 消散通知。

**边界**：tick 0、D-1、L=1/2、容量与寿命不一致、来源轮重复、暂停跨透明度、E1 同轮内提前移除。

**自动测试**：第 3 轮 E1+E2、第 4 轮 E2+E3；公式首刻/末刻；暂停 lifeProgress 不变；第三/五关第 3 轮 E1 是最后有效轮并于边界先消散。

**完成定义**：残影只在轮次边界加入/淘汰，透明度不参与玩法活跃判断。

### 5.6 R5：轮内快照与完整重开事务

**目标**：普通轮次只恢复轮内状态，整局重开彻底清空会话但保留存档。

**依赖**：开发 3 提供所有机关/射线/共振的快照数据与恢复端口；不得反射扫描未知对象。

**实施顺序**：进入关卡获取初始不可变快照 → 明确字段清单 → 普通轮恢复 → 校验占用释放 → 完整重开清单 → 场景退出清理 → 失败注入测试事务性。

**边界**：旧残影淘汰后仍占板、共振 LATCHED 泄漏、射线周期延续、方向/相位/提示残留、恢复半途异常、存档被误清。

**自动测试**：README 列出的玩家、队列、残影、录制、轮次、机关、共振、射线、相位、提示和计时逐项断言；存档状态保持。

**完成定义**：不依赖“重新 new 场景大概会清掉”；每个可变状态有所有者和清理断言。

### 5.7 R6：只读 RenderSnapshot 与场景清理

**目标**：让开发 1 绘制全部状态，但无法通过渲染引用修改时间系统。

**内容**：当前/残影位置、来源轮、remainingRounds、lifeProgress、轨迹降采样输入或缓存版本、射线、相位、共振、中继、核心和阶段。字段由各所有者提供，开发 2 只聚合经批准数据。

**实施顺序**：列渲染最小字段 → 采用不可变记录/不可修改集合 → 每逻辑刻或必要版本生成 → 场景结束解除生产者/监听器 → 开发 1 消费验证。

**边界**：集合外层不可变但元素可变、旧快照持有整个会话、渲染排序不稳定、alpha 被两方重复计算。

**自动测试**：修改返回集合会失败或不影响源状态；旧快照不随后台状态变化；场景清理后无回调；lifeProgress 只有开发 2 权威值。

**完成定义**：渲染零回写，且所需数据不迫使 Canvas 访问 replay/mechanism 内部对象。

### 5.8 R7：确定性诊断与发布修复

**目标**：功能冻结后用证据定位偏移和残留，只修阻塞/高优先级问题。

**诊断输出**：关卡 ID、currentRound、roundTick、记录期望/实际长度、sourceRound、事件排序键、状态摘要和首个分歧 tick。不得提交包含个人路径或隐私的原始日志。

**对照方法**：对同一输入脚本运行不同渲染时间序列；逐 tick 比较规范帧，找到首个分歧而不是只看终点。

**自动测试**：长时重复 100 次结果一致；暂停/恢复、重开、退出、五关切换无旧会话；失败注入不留半事务。

**完成定义**：修复带最小复现和回归测试；第 7 天后没有公共类型重构。

### 6.4 人工审查清单

- 是否存在除共享 `roundTick` 外的播放 elapsed/timer；
- 记录索引是否严格为 `0..D-1`，封装后是否真正不可变；
- RESULT、FAILED、重开、退出是否被错误复用普通轮封装逻辑；
- 射线命中是否误触发失败或截断录制；
- 残影是否重新计算输入、碰撞、autoDock 或射线；
- 寿命公式是否原样实现，是否只在边界淘汰；
- 轮内、会话、存档状态是否各有唯一所有者；
- 事务失败是否会暴露半完成状态；
- 测试是否覆盖首 tick、末 tick、暂停和轮次边界；
- 提交是否越过本板块或包含生成物、个人配置和无关格式化。

# R5 开工前裁决（PM）

> 发起：开发二｜裁决：PM｜日期：2026-09-10
> 分支：`feature/replay-r5-snapshot-contract`
> 基线核查：`d72a67e` 可达；本机 `origin/develop` 已到 `9bfd219`（bug-002 关卡中心修正），R5 基线请以 R5 分支实际基座为准。
> 事实核查：`snapshot/` 目前只有 `MechanismSnapshot`、`MvpRenderSnapshot`（无 R5 聚合）；`RecordingSession.recordEvent(TimelineEvent)` **已存在**；开发二所述 5 项 app 缺口属实。

## 裁决 1 · R5 所有权 → **批准**

**裁定**：
- **开发三**：各机关自己的**纯状态快照与 restore 能力**（`mechanism/**`，不暴露监听器/Canvas）。
- **开发二**：`snapshot/**` 下的**快照聚合、轮次事务编排、完整重开编排**。
- **app**：只**注入端口**，不持有快照语义、不改状态。

**理由**：README §十 目录归属（`snapshot/`=[开发2]，`mechanism/`=[开发3]）；开发二指南 §2.1/§5.6。**附加约束**：聚合只消费**经批准的只读快照数据**，禁止反射扫描未知对象（指南 §5.6）。

## 裁决 2 · 边界 tick 来源 → **批准（并明确为接口变更）**

**裁定**：废弃"Runnable 自己猜 tick"。改为：
- 开发二在**阶段切换之前**捕获**不可变 `TickContext`**：普通轮末 = **D-1** 的上下文；完整重开 = **操作发生时的当前上下文**。
- 连同**显式恢复原因**（如 `AutoDockResetReason`）交给 **typed restore port**；
- `RecordingSession.completeNormalRound(Runnable)` / `restartFromFirstRound(Runnable)` 演进为类型化端口（如 `restore(TickContext, RestoreReason)`）。

**流程要求**：这属**公共接口变更**，按 README §八「公共接口变更须提供方、使用方与项目经理确认」执行：开发二出签名提案 → 使用方（app/开发三）确认 → PM 批准后落地，并同步更新调用方。此裁决与开发一《C3-autoDock事件字段对齐确认》§6 的发现一致。

## 裁决 3 · R5 分段范围 → **批准，但必须分段命名**

**裁定**：
- 本段命名为 **R5-A「第一关快照基础」**（plate / door / exit + autoDock）。
- **不得**标记为"完整 R5"。Ray（P2）与共振/中继/核心（P4）快照端口补齐后，再做 **R5-B 全字段验收**。
- 交付物必须附**残余清单**（未覆盖机关与字段）。

**理由**：开发二指南 §5.6 要求逐项断言；README §七 冻结机关恰好 7 类，不能以 3 类冒充全量。

## 裁决 4 · tryLeave 语义 → **采用 README 优先（选项 A）**

**裁定**：
- 玩家**按下新的合法方向边沿时立即释放占用并记录 `DOCK_LEFT`**，**不等待位置出界**（对齐 README §三「离开驻留型机关时…对应占用同时释放」）。
- **另开任务**：主责**开发三**（放宽 `AutoDockOccupancyPort.tryLeave` 的 `NOT_OUTSIDE_REGION` 约束：占用者同刻按下合法出口即可释放），**开发一**配合在 `C3DockController` 于**离开刻**调用并记录事件。
- **开发二不写兼容分支**：只按事件的最终 `tick` 回放。

**理由**：README 优先级最高；测试/开发指南均要求 README 原样实现，不得以 API 现状反推玩法。

## 裁决 5 · PM 另开 app 集成任务 → **批准**

**裁定**：确认以下 app 缺口（本机核实为真），**PM 开独立 app 集成任务卡**，由集成层修，**开发二不得越权改 `app/**`**：

| # | 缺口 | 依据 |
| --- | --- | --- |
| a | `Level01Assembly` 未把 `C3DockDecision.events` 写入 `RecordingSession.recordEvent`（API 已存在） | README §九 事件记录 |
| b | 普通轮末后只到 READY，**未再进入 PLAYING**，下一轮不开始 | README §三 轮次切换 |
| c | 轮末**未恢复玩家位置/方向/队列** | README §三 |

3. **PM**：批准端口签名；开 **app 集成修复任务卡**（裁决 5）；追踪 R5-B 残余清单。

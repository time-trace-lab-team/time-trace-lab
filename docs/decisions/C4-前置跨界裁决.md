# C4 前置跨界裁决（PM）

> 发起：开发一｜裁决：PM｜日期：2026-09-10
> 议题：相位状态机归属、射线查询依赖方向、`LaserContact` 契约
> 依据：`README.md` §三/§五/§八/§十、`开发1-基础引擎与玩家-技术指南.md` §1.4/§2.1/§2.3、`开发3-玩法内容与界面-技术指南.md` §2.1
> 事实核查（本机实测）：三项均属实，且 `mechanism/ray/PhaseManager`、`mechanism/ray/RayManager` **全仓零引用**，`LaserContact` **全仓不存在**。

## 裁决 1 · 相位状态机归属 → **选项 A**

**裁定**：采用**选项 A**。开发一在 `entity/` 新建相位状态机（`PlayerPhaseController`），以既有 `core/ActorPhase{AVAILABLE,PHASED,RECOVERING}` 为唯一状态枚举，对外暴露 `ActorPhase`；**不修改** `mechanism/ray/PhaseManager`。

**附加要求**：`mechanism/ray/PhaseManager` 判定为**废弃冗余（死代码，零引用）**，记入清理清单，由**开发三**在其路径内删除（`mechanism/**` 属开发三）；开发一不得改。删除前不得有第二套相位状态机被使用。

**理由**：
1. README §十 模块归属把玩家/实体归 `core/entity`（开发1）；开发三指南 §2.1 明确「时滞射线」才是开发三主责，**玩家相位能力是开发一主责**（开发一指南 §2.1「当前玩家的 `PHASED` 操作状态与射线几何碰撞接入」）。
2. README §三 禁止第二套语义/时钟：`PhaseState` 与 `ActorPhase` 语义完全重叠（`NORMAL≡AVAILABLE`），不能并存。
3. 选项 B（迁移 `PhaseManager` 到 `entity/`）需开发一跨路径操作开发三文件、且迁移一个零引用死类无收益；新建 controller 更干净。

## 裁决 2 · 射线查询依赖方向 → **必须走窄只读端口**

**裁定**：
- **不允许** `core/**`、`entity/**` 直接 `import mechanism.ray.RayManager` / `mechanism.ray.Ray`。这会令玩法核心反向依赖机制实现，违反 README §八「单向依赖」与开发一指南 §1.4 的可测试核心要求。
- **开发一**在 `entity/`（或 `core/`）定义一个**窄只读端口**并让逻辑只依赖它，例如：
  ```java
  @FunctionalInterface
  interface RayContactQuery {
      boolean blockedAt(Vector2D position, double width, long tick);
  }
  ```
  由 **`app/` 集成层**用 `RayManager` 适配注入（`RayManager` 是单例，适配无成本）。
- **开发三本卡不新增接口**。若日后要把该端口升级为正式跨模块契约（提供方=开发三），由 PM 另开卡，不在 C4 内顺手扩。

**理由**：`RayManager` 零引用且返回具体 `Ray` 类；直接耦合会把开发一的碰撞判定绑死在开发三的实现上，违反「可测试核心」（端口可用假实现单测）。此方案**不需要任何开发三改动**，开发一可立即开工。

## 裁决 3 · `LaserContact` 契约 → **需要新建，但先出字段提案**

**裁定**：**需要新建**。按开发一指南 §2.3「`LaserContact`｜开发1/3｜只报告几何命中候选」：
- **归属开发一**，放在 `core/` 或 `entity/`（开发一路径），作为「几何命中候选」值类型，**不含任何减速结算**（结算归开发三）。
- 建议字段（**待 PM 确认后落地，开发一现在不写代码**）：
  ```text
  tick           long     命中发生的逻辑刻
  mechanismId    String   稳定射线 ID（开发三 ID 规则）
  actorId        String   "player"（残影不参与射线）
  phased         boolean  命中时是否处于 PHASED（命中候选在 PHASED 时应为空/被过滤）
  ```
- 与裁决 2 不冲突：`RayContactQuery` 是**开发三 → 开发一**的只读查询；`LaserContact` 是**开发一 → 开发三**的命中候选，方向相反、各放各的路径。
- 若 PM 认为第一关 MVP 不需要射线，可把本项顺延到第二关（C4 正式卡）再冻结；但**类型归属仍按上述**，不得放到 `mechanism/**`。

## 执行顺序（裁决后）

1. 开发一：按裁决 1 新建 `entity/PlayerPhaseController`（用 `core.ActorPhase`，30/45 tick 边界）；按裁决 2 定义窄端口 `RayContactQuery`；按裁决 3 出 `LaserContact` 字段提案。
2. 开发三：在其路径内删除废弃的 `PhaseManager`（零引用，删除后测试须仍全绿）。
3. PM：把裁决 2 的端口是否升级为正式契约、以及 `LaserContact` 最终字段，记入接口决策；必要时另开卡。

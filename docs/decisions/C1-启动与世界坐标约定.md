# C1 启动与世界坐标约定

- 状态：已确认
- 日期：2026-09-09
- 决策人：项目经理 / 架构与集成
- 适用模块：`app`、`core`、`render`、`level`

## 1. 最小 JavaFX 启动壳

- 启动类固定为 `org.example.timeloop.app.TimeTraceLabApplication`。
- 启动壳只装配一个 `Stage`、一个 `Scene`、一个 `Canvas` 和一个
  `AnimationTimer`，不实现菜单、页面切换或关卡选择。
- `AnimationTimer.handle(long nanoTime)` 将 JavaFX 提供的纳秒时间戳原样交给
  固定步长时钟，不在 `app` 层换算单位。
- 远端 `feature/core-c0` 的 `0c61746` 中实际接口是
  `FixedStepClock.advance(long nanoTime, GamePhase phase)`，没有
  `FixedStepLoop.onAnimationFrame(...)`。因此当前启动壳按已提交、可编译的实际
  接口接入；若开发 1 在 C1 新增 `FixedStepLoop`，应由该模块任务把这一处调用
  替换为最终接口，不并存两套固定步长时钟。

## 2. Canvas 与世界坐标

- `Canvas.getWidth()/getHeight()` 表示当前 JavaFX 画布的布局/绘制尺寸；它是
  JavaFX 逻辑像素，高 DPI 下不等同于物理屏幕像素。
- `CanvasAdapter.renderFrame(worldW, worldH, alpha)` 中的 `worldW/worldH`
  表示世界逻辑尺寸，不表示画布像素尺寸。
- 默认世界为 `20 × 12` 格，`tileSize = 48` 个世界逻辑单位，因此默认世界尺寸为
  `960 × 576`。最小窗口初始画布同为 `960 × 576`，初始缩放为 1:1。
- 窗口尺寸改变后，由渲染边界统一计算等比缩放和居中留边，再让所有世界图层
  共用同一变换；各图层不得各自重复换算。
- 路径节点、玩家、墙、门、机关、射线和共振判定始终使用世界坐标。画布缩放、
  高 DPI、轨迹错位和视觉投影不得回写碰撞坐标。
- `PathNode` 与 `Vector2D` 中的坐标是世界坐标。关卡数据的 `tileSize` 必须写为
  `48.0`；开发 3 的 `feature/content0` 当前暂写为 `64.0`，且源码已标记“待确认”，
  合并前需由开发 3 在自己的板块任务中统一为 `48.0`。

  `GamePhase` 或 `FixedStepClock`。当前实现已经保证只有 `PLAYING` 推进。
